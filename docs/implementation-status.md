# 구현 현황과 남은 작업

기준일: 2026-09-15 · 앱 버전: 0.1.0 · 운영 배포 기준: `7282d9a` ([번들 발행 자동화 #11](https://github.com/team-campfire-dev/geunyang-math/pull/11)) · 운영 콘텐츠 기준: 클래스 v4 판본.

현재 운영 웹은 **Google 로그인 → 선택형 시작점 진단 → 규칙 기반 추천 → 클래스 학습 → 개인 복습 과제 → 제출·기록 복원**을 제공한다. 본문 용어에 진행도에 따라 풀이를 붙이는 기능과 수식 표기를 배포했고, 운영 콘텐츠도 이를 사용하는 v4 판본으로 발행했다. 기본 콘텐츠의 운영 원본은 DB이며, 사람용 클래스 편집기와 AI 생성기는 아직 없다. 성인 기초 재학습에서 시작해 콘텐츠 형식과 학원·학교용 과제로 확장한다는 [제품 방향](product-direction.md)을 따른다.

## 학습·평가·개인화

운영 웹은 Google 계정으로 로그인하고 목표와 하루 5·10·20분 설정을 저장한다. 시작점 진단은 선택 사항이다. 기본 진단은 분수의 의미·동치/약분·덧셈을 각 2문제로 확인한다. 문항·제목·설명·문항 수·예상 시간은 DB에서 읽으며, 진행 중 진단은 시작 당시 snapshot으로 이어간다. 유효한 답안은 변경할 수 없고 건너뛰기는 미확인이다. 결과는 완료 후 공개한다.

추천용 준비 상태는 진단보다 실제 수업·확정 과제의 첫 유효 풀이를 우선한다. 선수개념이 준비된 진행 중 수업을 이어가거나, 아직 준비되지 않은 개념의 수업을 제안한다. 학습자는 다른 수업을 직접 고르고 자동 추천으로 돌아갈 수 있다. 목표는 제공 개념이 모두 준비됐을 때의 제안에, 시간은 오늘의 진행 안내와 새 과제 분량에 반영한다. 계산한 `plan`은 별도 LearningPlan 테이블에 저장하지 않지만, 선택은 `User.preferredClassKey`, 변경 이력은 `RecommendationHistory`에 보존한다. 화면은 최근 10개 이력을 보여준다.

수업은 앞 단계를 완료해야 뒤 활동으로 이동한다. 필수 문항에 유효한 시도가 있으면 오답이어도 단계 완료가 가능하다. 채점은 서버의 정수·유리수 계산을 사용하며 파싱 오류와 오답, 기약분수 요구를 구분한다. 부동소수점 근사 비교나 사용자 수식 실행은 사용하지 않는다. 답안은 평문과 함께 `\frac{1}{2}`, `$...$`, `\(...\)` 같은 LaTeX 표기를 받는다. 정수로만 이루어진 분수 하나를 구문 치환으로 풀어 쓸 뿐이므로 `\frac{1+1}{4}`처럼 계산이 필요한 입력은 오답이 아니라 파싱 오류가 된다. 수식 입력기 화면은 아직 없다.

수강 완료는 transaction 안에서 개인 복습 과제·배정·첫 draft Submission을 함께 만든다. 5분 설정은 1문제, 10·20분은 현재 문항 풀에서 최대 2문제다. 첫 풀이와 도움 사용에 따라 1일 또는 3일 뒤를 권장한다. 권장 시점은 마감·잠금 시각이 아니며 미리 풀 수 있다. 과제의 모든 문항에 유효한 답안이 있어야 최종 제출할 수 있다. 확정한 Attempt는 SubmissionItem에 고정하고 이후 새 풀이·힌트 추가를 거부한다. 재제출 회차 생성과 반복 복습 자동 배정은 아직 없다.

추천용 `plan.readiness`와 연습·직접 해결·지연 복습을 나타내는 `skills`는 구분한다. 진단만으로 숙달이나 클래스 완료를 인정하지 않는다. 반복 정답으로 첫 오답을 지우거나 독립 증거 수를 늘리지 않는다. 이 기준의 학습 효과는 아직 검증하지 않았다. 상세 규칙과 한계는 [개인화](personalization.md)를 따른다.

## 콘텐츠와 데이터 보존

기본 클래스는 **분수, 전체와 조각의 관계**, **모양이 달라도 같은 분수**, **분수 더하기, 조각 크기 맞추기**다. 지원 블록은 `core.rich_text@1`, 용어 주석을 담는 `core.rich_text@2`, `core.problem_set@1`, 분수 막대 primitive의 `core.figure@1`, `math.fraction_strip@1`, 같은 막대를 장면으로 이어 보여주는 `math.fraction_sequence@1`, 학습자가 칸을 채우는 `math.fraction_builder@1`이며 rich text와 도형 캡션의 수식을 KaTeX로 표시한다. 캡션에 수식을 쓰면 화면 낭독용 이름은 평문으로 따로 둔다. `core.figure@1`은 `alt`가, `math.fraction_strip@1`은 `labelAlt`가 그 역할을 하며 어느 쪽이든 빠지거나 수식이 섞이면 발행을 거부한다. 필수 미지원 블록은 발행 검증에서 거부하고, 브라우저도 처리하지 못한 필수 활동을 완료하지 않는다. 선택 블록은 대체 설명을 사용한다.

움직이는 막대와 조작 블록은 앱에만 구현했고 운영 콘텐츠는 아직 사용하지 않는다. 재생·멈춤·앞뒤 이동 버튼은 항상 함께 그리며 `autoplay`는 동작 줄이기 설정에 양보한다. 조작 블록은 누르기를 기본 동작으로 두고 마우스 드래그를 더하며, 손가락으로는 드래그가 시작되지 않으므로 터치 기기에서는 조각 트레이를 감춘다. 놓은 조각은 **서버로 보내지 않는다**. 진도·학습 증거·개인화에 반영하지 않고 단계 완료를 막지도 않으며, 채점은 종전대로 문항에서만 한다. 그래서 문항 본문·힌트·해설과 용어 풀이에 조작 블록을 넣으면 발행을 거부한다. 조작 결과를 학습 기록으로 받으려면 저장 형식과 채점·개인화 규칙을 따로 설계해야 한다.

`ClassVersion.document`는 수업 정보와 비공개 문제·힌트·해설·채점 규칙을 가진 불변 JSON 문서다. `DiagnosticVersion`은 진단 정의, `Skill`은 개념 이름·순서를 제공한다. 공개 카탈로그 응답은 발행된 클래스가 가르치는 개념 이름을 함께 제공하므로 로그아웃 화면의 소개 문구도 DB를 따른다. 클래스가 아직 없는 개념은 공개 응답에서 제외한다. 런타임의 하드코딩 seed는 제거했고, 배포 시 `db:migrate → content:verify`를 실행한다. `db:seed`는 읽기 전용 검증 호환 명령이다.

콘텐츠 CLI는 기존 판본과 같은 문제 ID의 다른 내용을 거부하고 등록 전체를 하나의 transaction으로 처리한다. 수정은 새 판본 ID로 발행한다. 기존 클래스 해시·발행 시각은 그대로 유지한다. 이 불변성은 등록·서비스 경로의 규칙이며, DB 관리자가 직접 SQL로 변경하는 것을 차단하는 trigger는 없다.

```text
Skill                         → 개념 이름·표시 순서
DiagnosticVersion             → DiagnosticRun.document + answers
개인 Scope → Enrollment       → ClassVersion.document
개인 Scope → Assignment       → AssignmentItem.problemSnapshot
                └─ AssignmentRecipient → Submission
                                            ├─ Attempt
                                            └─ SubmissionItem: 확정 Attempt
```

독립 `ProblemVersion` 테이블은 아직 없다. 문항은 클래스 판본에 포함되며 과제에 snapshot으로 복사한다. 공개 DTO는 정답·채점 명세·미공개 해설을 제외한다. 독립 과제는 서비스·통합 테스트에서 수강 없이 생성 가능하지만 현재 화면/API의 자동 배정은 수강 완료 시 개인 복습에 한정한다. 과제 정책 필드가 교사용 권한·편집 엔진의 구현을 뜻하지는 않는다.

용어 풀이는 별도 `TermVersion` 판본으로 발행하고 본문은 `core.rich_text@2` 블록에서 `termKey`로 참조한다. 서버는 지금 배우는 클래스가 가르치는 개념과 과제가 평가하는 개념의 용어를 응답에서 제외하고, 선수 개념이나 더 앞 순서 클래스의 개념만 내려보낸다. 진단에서는 용어 풀이를 제공하지 않는다. 용어 정의는 판본을 고정하지 않고 항상 최신 판본을 조회한다. 채점과 무관한 보조 설명이므로 정정이 즉시 반영되는 쪽을 택했고, 이는 클래스·문항 불변 규칙의 명시적 예외다. 용어 열람은 힌트로 기록하지 않으며 개인화에도 사용하지 않는다.

`/authoring` 화면에서 발행된 클래스의 다음 판본을 초안으로 만들고, 블록을 폼으로 고치고, 학습 화면과 같은 렌더러로 미리 보고 발행한다. 화면은 CLI와 같은 `importContent`를 호출하므로 검증·참조 검사·불변 규칙·트랜잭션이 동일하다. 편집 권한은 계정이 가진 역할(`admin`은 발행까지, `author`는 자기 초안까지)이며, 역할이 없는 계정에는 화면도 목록도 열리지 않는다. 첫 관리자는 `CONTENT_ADMIN_SUBJECTS`로 지정하고 나머지는 `ContentAuthor` 행으로 부여한다. 아직 사용자가 없는 배포를 위해 `CONTENT_OPEN_ACCESS=true`로 로그인·권한 없이 여는 스위치를 두었다. 켜면 경로를 찾은 누구든 발행·삭제할 수 있으므로 접근 제어가 아니며, 공개 전에 끄고 역할 기반 권한으로 돌아가야 한다. 교사 권한이 생기면 같은 역할을 그 계정에 주면 되고 화면과 API는 그대로다. 초안은 기준 판본을 복사해 만들며 **문항·채점 규칙·힌트·해설은 서버에 남고 브라우저로 내려가지 않는다**. 새 클래스 작성, 문항·정답·힌트·해설 편집, 진단·용어 편집은 아직 화면에 없고 CLI 경로를 쓴다.

콘텐츠 추가는 [DB 콘텐츠 관리](content-management.md)의 등록·내보내기 명령도 그대로 사용한다. 기존 블록으로 만든 새 콘텐츠는 앱 재배포 없이 제공할 수 있고, 새 블록 종류는 서버 검증과 공용 렌더러 배포가 필요하다.

## 인증·모바일·운영

Google 웹 로그인과 같은 계정의 설정 저장·로그아웃·재로그인 복원을 운영에서 확인했다. 계정은 Google `sub`로 연결하며 이메일이나 이름으로 다른 Google/개발 계정을 병합하지 않는다. 일회용 state·PKCE·nonce·공식 ID 토큰 검증, 7일 Secure·HttpOnly·SameSite=Lax 세션, origin·화면 계정 일치 검사를 적용한다. Google access/refresh token은 보관하지 않는다. 개발 로그인은 development·명시적 플래그·loopback 조건에서만 허용하며 운영에서는 비활성이다.

동의 화면은 기존 Google 프로젝트의 공유 이름 **Constella**를 사용한다. 사용자 결정에 따라 이름 변경은 후속 작업으로 남긴다. 전용 OAuth 클라이언트와 DB 자격증명은 다른 프로젝트와 분리했다. 설정·NPM·TLS·복구 절차와 릴리스 이력은 [배포 문서](deployment.md)에 모았다.

웹·모바일은 같은 공개 HTTP 계약과 UI를 사용한다. 모바일 정적 export는 성공했으나 native 앱·인증·CORS·오프라인 큐·OTA는 미구현이다. 현재 개인화와 콘텐츠는 서버에서 조회하므로 모바일 번들에 진단·정답 원본을 넣지 않는다. 자세한 구현 경계는 [모바일 구조](mobile-architecture.md)를 따른다.

## 검증 기준

[DB 콘텐츠 전환 릴리스 실행](https://github.com/team-campfire-dev/geunyang-math/actions/runs/34811307476)을 기준으로 아래를 확인했다. 이 문서 수정 자체가 새로운 기능 검증이나 학습 효과 검증을 의미하지 않는다.

| 확인 | 결과 |
|---|---|
| 타입·자동 테스트 | MySQL 통합 검사를 포함한 190개 전체 통과 |
| 배포용 migrator | 권한 600/700 archive에서 non-root 실행, 신규 DB migration·콘텐츠 검증 통과 |
| 기존 DB 업그레이드 | 이전 릴리스의 클래스 행·해시·발행 시각·진도·과제·진단 snapshot/답안이 전후 동일 |
| 콘텐츠 관리 | DB만으로 새 클래스·개념·진단 제공, dry run 무변경, export 재등록·불변 판본·참조 검증 |
| 웹·모바일 | 운영 웹 빌드와 모바일 정적 export 성공, 모바일 결과에 기본 문항·채점 규칙 미포함 확인 |
| 운영 배포 | Oracle 배포·DB migration 성공, 공개 health 정상과 정확한 commit 확인 |
| 운영 콘텐츠·화면 | 공개 클래스 3개·블록·15문항의 이전 내용과 일치, 기존 계정의 학습 상태·진단 결과·진도 로드 확인 |
| 실제 Google 로그인 | OAuth 릴리스에서 설정 저장→로그아웃→같은 계정 재로그인 복원 확인 |
| 실제 모바일·학습 효과 | 아직 검증하지 않음 |

용어 풀이와 수식 표기는 위 릴리스 이후의 변경이다. 타입·전체 236개 테스트·웹/모바일 빌드를 통과했고, 운영 배포와 v4 콘텐츠 발행까지 마쳤다. 공개 API에서 카탈로그가 v4이고 수식·용어 주석·glossary가 내려오는 것, 화면에서 수식이 조판되고 선수 개념 용어에만 밑줄이 붙는 것을 확인했다. 앱 배포보다 콘텐츠 발행이 앞서면 구버전 클라이언트가 `core.rich_text@2`를 가진 클래스를 열지 못하므로 순서를 지켰다.

이미 수강을 시작한 계정은 그 판본에 고정되므로 v4를 보려면 새로 수강해야 한다. 2026-09-15에 운영 계정 데이터를 전체 삭제했고 콘텐츠는 보존했다. 자세한 실행 기록은 [배포 문서](deployment.md)를 따른다. 학습 효과와 용어 노출 기준의 타당성은 여전히 검증하지 않았다.

장면을 이어 보여주는 막대와 조작 블록은 그 뒤의 변경이다. 타입 검사와 전체 248개 중 204개 테스트(MySQL 통합 44개는 DB 없는 환경이라 건너뜀), 웹 빌드와 모바일 정적 export를 통과했다. 브라우저에서 자동 재생·멈춤·앞뒤 이동, 칸 누르기로 놓기·빼기, 목표 도달과 초과 안내, 처음으로 되돌리기, 375px 화면에서의 배치와 터치 기기의 트레이 숨김을 직접 확인했다. 운영 콘텐츠에는 아직 이 블록이 없고, 발행하려면 이 앱을 먼저 배포해야 한다. 학습 효과와 교구로서의 타당성은 검증하지 않았다.

편집·미리보기·발행 화면은 그다음 변경이다. 타입 검사와 MySQL 통합을 포함한 전체 270개 테스트, 웹 빌드, 모바일 정적 export를 통과했다. 로컬에서 실제로 초안 만들기→블록 추가→미리보기→저장→검증→발행까지 수행해 새 `ClassVersion` 행이 생기고 학습 화면이 그 판본을 그리는 것을 확인했다. 로그인 없이 여는 스위치도 로그아웃 상태에서 화면이 열리고 초안이 공용 계정으로 저장되는 것까지 확인했다. 권한 없는 계정에 화면이 닫히는 것, 초안 응답에 정답·채점 규칙·해설이 들어가지 않는 것, 발행된 판본 ID로는 발행이 거부되는 것은 자동 테스트로 확인한다. 운영에는 아직 배포하지 않았고 권한을 받은 계정도 없다.

DB 없는 테스트는 MySQL 통합 검사만 건너뛴다. 전체 검증 명령과 별도 `_test` DB 준비 방법은 [README](../README.md)에 있다. 과거 161개(OAuth), 179개(개인화) 검증은 각 릴리스의 기록이며 현재 전체 개수와 구분한다.

## 다음 구현 순서

1. DB 등록 경로로 진단·수업·복습 문항을 검수·확대하고, 성인 학습자 파일럿으로 개인화 규칙과 용어 노출 기준을 검증한다. 백업 복원 훈련과 계정 삭제 절차를 병행한다. 계정 데이터를 전체 삭제한 뒤라 복원 수단이 없는 상태가 드러났다.
2. 현재 1회 복습 이후 반복 복습과 상세 오류 유형별 보충을 확장한다.
3. 편집 화면 위에 새 클래스·문항 작성과 검수·승인 흐름을 얹는다. 콘텐츠 정정·재채점·사용자 안내 절차를 연결한다.
4. 사용 사례에 따라 그래프·도형 블록, 기관 배정·평가, 모바일 runtime·인증을 확장한다.
5. 편집기와 학습 기록이 안정되면 AI가 같은 클래스 초안 형식을 작성하도록 연결한다. AI와 기관 확장은 서로의 선행조건이 아니다.
