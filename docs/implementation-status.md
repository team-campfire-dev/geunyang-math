# 첫 구현 현황

기준일: 2026-09-14 · 앱 버전: 0.1.0

현재 결과는 **개인 학습과 복습 과제를 한 흐름으로 검증하는 첫 구현**이다. 클래스 구조를 먼저 만들고 편집기·AI 작성자로 확장한다는 방향, 다양한 콘텐츠 형식과 학원·학교용 과제 구조를 준비한다는 방향은 유지한다. 전체 개인화 제품이나 학교용 서비스의 완성을 의미하지 않는다.

설계의 출발점은 같은 날짜에 검토한 `geunyang-math-plan.md`, `implementation-roadmap.md`, `final-plan-review.md`의 v0.2다. 이 문서들은 대화 산출물이며 현재 저장소에 원본을 복사하지 않았다. 합의한 핵심 방향은 [제품 방향](product-direction.md)에 기록했다. 아래 표는 당시 계획과 현재 코드의 차이를 명시한다.

## 현재 가능한 학습 흐름

개발 서버의 loopback 주소에서 개발용 학습자를 만든다. 목표와 하루 5·10·20분 설정을 저장하고, 클래스 하나를 시작한다. 서버는 수강한 클래스 판본을 고정하고 앞 단계를 완료해야 뒤의 활동을 진행할 수 있도록 확인한다.

문항은 서버에서 정수·유리수로 판정하며 부동소수점 근사 비교나 수식 실행을 사용하지 않는다. 파싱 실패와 오답을 구분하고 기약분수 요구를 검사한다. 정답을 맞혀야만 다음 단계로 갈 수 있는 구조는 아니다. 각 필수 문항에 유효한 시도가 있으면 단계 완료가 가능하다.

수강 완료는 transaction 안에서 개인 복습 과제·배정·첫 draft Submission을 함께 만든다. 권장 시점은 완료로부터 24시간 뒤이며, 마감이나 잠금 시각은 아니다. 미리 과제를 풀 수 있지만 권장 시점 전에 낸 답안은 지연 복습 성공으로 취급하지 않는다. 과제의 답안 저장과 최종 제출은 분리되어 있고, 모든 문항에 유효한 답안이 있어야 최종 제출할 수 있다.

같은 요청의 재전송과 동시 수강 완료를 중복 생성으로 처리하지 않는다. 제출 확정 시 선택한 Attempt를 SubmissionItem에 고정하며, 확정 후 새 풀이·힌트를 추가하는 요청은 거부한다. 재제출을 위한 다음 Submission 생성은 아직 제공하지 않는다.

## 콘텐츠·데이터 경계

현재 클래스는 다음 세 개다.

1. **분수, 전체와 조각의 관계** — 분수의 의미
2. **모양이 달라도 같은 분수** — 동치분수와 약분
3. **분수 더하기, 조각 크기 맞추기** — 분수의 덧셈

초기 표현 형식은 `core.rich_text@1`, `core.problem_set@1`, 분수 막대 primitive를 담은 `core.figure@1`, `math.fraction_strip@1`이다. rich text 안의 수식을 KaTeX로 표시한다. 일반 그래프·도형 엔진이 구현된 것은 아니다. 새 형식은 서버 payload 검증과 브라우저 렌더러를 함께 추가해야 한다.

필수 미지원 블록은 발행 데이터 검증에서 거부하고, 브라우저가 필수 블록을 처리하지 못하면 해당 활동 완료를 막는다. 선택 블록의 미지원 형식은 대체 설명을 사용한다. 편집 UI, 허용 위치 정책 전체, 외부 플러그인 로딩은 없다.

`ClassVersion.document`에는 공개 수업 정보와 서버 전용 문제·힌트·해설·채점 규칙이 함께 들어간다. seed는 기존 판본의 hash가 다르면 덮어쓰지 않고 실패한다. 콘텐츠 수정은 새 version ID를 만드는 방식이다. 이는 현재 seed/서비스 경로의 불변성 규칙이며, DB 관리자가 직접 JSON을 변경하는 것까지 막는 데이터베이스 trigger는 없다.

문제에 `problemVersionId`는 있지만 **독립된 ProblemVersion 테이블은 없다.** 클래스 안의 문제 JSON이 발행 판본에 포함되고, 과제에는 `AssignmentItem.problemSnapshot`으로 문제 내용을 고정한다. 공개 응답을 만들 때 정답·`gradingSpec`·비공개 solution을 제거한다. 원본 콘텐츠는 `server-only` 경계에 두며 채점 코드는 서버 서비스에서 호출한다. 두 코드군 모두 모바일 빌드의 복사 대상에서 제외한다.

```text
개인 Scope → Enrollment → ClassVersion.document

개인 Scope → Assignment → AssignmentItem.problemSnapshot
               └─ AssignmentRecipient
                      └─ Submission
                             ├─ Attempt: 개별 답안·판정·힌트 사용
                             └─ SubmissionItem: 확정한 Attempt 선택
```

독립 과제는 `createPersonalAssignment` 서비스와 통합 테스트에서 수강 없이 생성·풀이할 수 있음을 확인했다. 현재 공개 HTTP API와 화면의 자동 생성 경로는 수강 완료 시 개인 복습에 한정한다. `assignmentPolicy`, `policySnapshot`, `issuerType` 등의 필드는 확장 지점이며, 완성된 교사용 정책 편집·권한 엔진은 아니다. 개인 과제의 내용·마감 등을 바꾸는 API도 아직 없다.

## 개인화의 현재 수준

추천은 진행 중 클래스가 있으면 그 수업을 선택한다. 없으면 완료하지 않은 클래스를 기본 순서로 최대 두 개 반환한다. 목표와 학습 시간은 안내 문구에 반영한다. 선수개념·오답에 따른 클래스 순서 변경이나 시간에 맞춘 문항 수 조정은 아직 하지 않는다. 별도 LearningPlan 테이블과 추천 변경 이력도 없다.

학습 증거는 첫 유효 시도를 사용하며 힌트 뒤에 얻은 정답을 독립 성공으로 계산하지 않는다. 서로 다른 확인퀴즈·확정 과제 문항에서 무힌트 첫 유효 시도 정답이 두 개 이상이면 직접 해결 상태가 된다. 확정 제출한 과제에서 권장 시각 이후의 독립 성공과 수업의 독립 성공이 함께 있으면 지연 복습 상태로 올린다. 과제만 푸는 경우도 유효한 시도가 있으면 연습 중 상태가 된다. 이 기준은 초기 규칙이며 전문가 검토와 파일럿을 통한 학습 효과 검증은 아직 필요하다.

## 인증·모바일·운영 상태

실제 Google OAuth는 없다. 개발용 로그인은 `NODE_ENV=development`, `DEV_LOGIN_ENABLED=true`, loopback 호스트일 때만 동작한다. production에서는 플래그를 켜도 사용할 수 없다. 화면에서 이름을 입력하는 것은 OAuth나 기존 사용자 확인 절차가 아니며, 세션이 사라진 뒤 기존 학습자 계정으로 재접속하는 용도로 사용할 수 없다.

모바일 정적 export는 실행해 성공했다. 서버 API·DB·정답 seed를 제외한 HTML/CSS/JS 번들이 `out/`에 생성된다. 하지만 `capacitor.config.ts`와 CLI 설치만으로 실행 가능한 native 앱이 완성된 것은 아니다. Capacitor runtime, iOS/Android 프로젝트, native 인증 어댑터·CORS·딥링크·보안 저장소는 후속 작업이다. 현재 cookie 기반 API를 native에서 그대로 사용할 수 있다고 보장하지 않는다.

오프라인 저장·제출 큐와 OTA도 없다. 네트워크 오류는 오류로 표시하고 서버 접수를 확인하기 전 제출 완료로 처리하지 않는다. 자세한 모바일 경계는 [모바일 구조 문서](mobile-architecture.md)를 따른다.

Docker Compose는 별도 로컬 MySQL을 실행한다. 앱 Dockerfile이나 Oracle 운영 배포는 아직 만들지 않았으며 기존 프로젝트의 운영 DB·OAuth 자격증명·배포 환경을 가져오지 않았다. 운영을 시작하려면 인증, TLS와 도메인, 전용 DB 계정, 백업·복구, 데이터 보관 정책, 관측과 rate limit을 준비해야 한다.

## 다음 구현 순서

1. 웹의 실제 Google 로그인과 계정 재접속·관리 기능을 연결하고, 콘텐츠를 전문가가 검수한다.
2. 진단·선행개념·오답·가용 시간에 따라 추천 순서와 복습 분량이 실제로 달라지게 만들고 추천 이력을 남긴다.
3. 콘텐츠 import·초안·검수·새 판본 발행 경로와 콘텐츠 오류 정정·재채점 흐름을 만든다. 그 위에 사람용 편집기를 연결한다.
4. 사용 사례에 따라 그래프·도형 형식, 기관 배정·평가, 모바일 runtime·인증을 각각 확장한다.
5. 편집기와 학습 기록이 안정된 뒤 AI가 같은 클래스 초안 형식을 작성하도록 연결한다. AI 도입과 기관 확장은 서로의 선행조건이 아니다.

공개 파일럿의 시작은 첫 화면이나 빌드 성공만으로 결정하지 않는다. 계정 재접속, 학습 기록 보존, 콘텐츠 검수, 실제 배포·복구와 핵심 학습 흐름까지 확인한 뒤 진행한다.
