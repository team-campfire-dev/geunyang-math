# 규칙 기반 개인화 v1

2026-09-14. AI 호출 없이 현재 분수 클래스 3개에 적용한다. 추천은 제안이며, 수강 가능 여부나 성적·숙달 판정을 제한하지 않는다.

## 사용자 흐름

- 내 학습 → 6문제로 확인하기. 분수 의미·동치/약분·덧셈을 각각 2문제로 확인한다. 진단은 선택 사항이며 중단 후 이어갈 수 있다.
- 유효한 답안은 한 번 저장하며 변경하지 않는다. 입력 오류는 진행을 막지만, 오답과 건너뛰기는 다음 문제로 진행한다. 건너뛰기는 미확인으로 남긴다. 진단 결과는 완료 후 공개한다.
- 추천 이유와 개념별 준비 상태를 확인한다. 클래스 목록에서 다른 수업을 직접 추천으로 고르거나 자동 추천으로 복귀한다. 고른 수업을 완료하면 자동 추천으로 돌아간다.
- 실제 수업·제출한 복습의 풀이가 진단보다 우선한다. 하루 학습 시간은 오늘의 진행 안내와 새 과제 분량에 반영하며 필수 설명·활동을 삭제하지 않는다.
- 학습 기록에서 추천이 달라진 이유를 최근 10개까지 확인한다.

## 추천 기준

`src/core/personalization.ts`의 결정적 규칙을 서버가 실행한다.

1. 진단의 한 개념에서 2문제를 모두 맞혔으면 잠정적으로 다음 개념을 시작할 준비가 됐다고 본다. 오답이 있으면 연습 필요, 건너뛴 문제만 있거나 근거가 부족하면 미확인이다. 진단만으로 클래스 완료나 독립 해결·장기 기억 상태를 주지 않는다.
2. 실제 풀이가 있으면 첫 유효 시도만 사용한다. 확인 퀴즈·최종 제출된 복습을 연습보다 우선하며 최신 평가 묶음의 해당 개념 문항을 모두 도움 없이 맞혔는지 본다. 이후 재시도 정답으로 최초 오답을 지우지 않는다. 복습 초안·미제출·입력 오류는 새로운 평가 근거로 사용하지 않는다.
3. 아직 준비되지 않은 개념 중 선수개념이 준비된 수업을 기본 순서로 추천한다. 이어가던 수업의 선수개념이 미확인이면 먼저 확인할 수업을 안내한다. 수업 목록에서 직접 시작하는 것은 막지 않는다.
4. 직접 고른 추천 수업은 선택을 해제하거나 그 수업을 완료할 때까지 유지한다. 아직 확인하지 않은 선수개념이 있으면 함께 안내한다.
5. 제공 중인 개념이 모두 준비됐으면 생활/기초 목표는 첫 일상 예제 수업, 대수 준비 목표는 마지막 분수 계산 수업을 제안한다. 현재 과정이 선형이고 3개뿐이므로 목표별 별도 과정은 아직 없다.
6. 권장 시점이 지난 미제출 복습이 있으면 내 학습에서 먼저 제안한다. 늦은 제출을 오답이나 실패로 해석하지 않는다.

기존 `skills`의 연습·독립 해결·지연 복습 상태와 추천용 `plan.readiness`는 구분한다. 추천용 준비는 작은 근거로 다음 수업을 제안하는 값이며 검증된 숙달 점수가 아니다.

## 새 복습 과제

- 하루 5분은 1문제, 10·20분은 최대 2문제다. 현재 클래스별 복습 문항이 2개이므로 그 이상 생성하지 않는다.
- 클래스의 첫 유효 풀이에서 어려움이 있었던 skill·응답 형식과 맞는 숙제 문항을 먼저 고른다. 현 단계는 상세 오개념 분류가 아니라 기존 문항 풀의 선택이다.
- 확인 퀴즈가 있고 모든 첫 유효 풀이를 힌트 없이 맞혔으면 3일 뒤, 오답·도움 사용이 있거나 근거가 부족하면 1일 뒤를 권장한다. 이 간격은 검증할 초기 규칙이지 학습 효과가 입증된 최적 간격은 아니다.
- 선택한 문항·시간 설정·간격·이유·규칙 버전을 발행 시점의 `Assignment.policySnapshot`과 문항 snapshot에 고정한다. 이미 배정된 과제의 내용·시점은 설정이나 추천이 바뀌어도 수정하지 않는다.
- 클래스 완료로 1회 복습을 배정한다. 주기적으로 새 과제를 생성하거나 같은 문항 반복 정답을 새 독립 증거로 인정하는 기능은 이번 범위가 아니다.

## 저장 및 API

- `DiagnosticRun`: 사용자와 진단 판본별 1개. 별도 진단 문항 6개의 서버 전용 snapshot, 저장한 답·건너뛰기, 진행·완료 시점을 보관한다. 수업·퀴즈·숙제 문항과 ID를 공유하지 않는다. 같은 판본을 다시 시작해 점수를 반복 올릴 수 없다.
- `User.preferredClassKey`: 직접 고른 추천. 서버가 공개 클래스 존재를 확인하며 타인 설정을 수정할 수 없다.
- `RecommendationHistory`: 학습/설정 mutation과 같은 serializable transaction 안에서 추천·준비 상태·시간·우선 복습 snapshot이 달라질 때만 추가한다. 답안 원문은 이 이력에 넣지 않는다. GET은 계산·조회만 하며 시각 경과만으로 이력 행을 쓰지 않는다. 화면은 최근 10개, DB에는 기존 이력을 보존한다.
- 기존 `POST /api/v1/learning`에 `diagnostic.start`, `diagnostic.answer`, `recommendation.choose`를 추가했다. 기존 세션·same-origin·화면 계정 일치 보호를 그대로 적용한다.
- 진단 답안은 현재 문항 순서를 서버에서 검사한다. 동일 문항·동일 답 재전송은 동일 결과, 다른 답으로 변경은 충돌이다. 동시 요청은 기존 transaction 재시도로 처리한다.
- 공개 상태에는 현재 진단 문항만 포함하고 정답·채점 명세·미공개 해설을 전송하지 않는다. 미완료 상태에서 진단 결과도 전송하지 않는다. 완료 후에는 본인의 답과 맞음/틀림/건너뛰기를 보여준다.
- 마이그레이션은 두 테이블과 User의 nullable 열 추가만 수행한다. 기존 클래스·수강·과제·답안 데이터는 수정하지 않는다. 기존 seed 판본도 변경하지 않았다.

## 검증

로컬 전체 검사 179개와 TypeScript 검사, 웹 빌드·모바일 정적 export가 통과했다. 브라우저에서 진단 저장·재접속·추천 변경·직접 선택과 자동 복귀를 확인했고, 390px 화면에서 가로 넘침과 콘솔 오류가 없음을 확인했다. 배포 결과는 해당 릴리스의 GitHub Actions를 따른다.

개인화 단위 검사, 실제 MySQL의 진단 저장·계정 격리·동시 재전송·추천 변화·직접 선택·과제 보존 검사를 기존 전체 테스트와 함께 실행한다. 웹 빌드와 별도의 모바일 정적 export를 확인한다. 실제 브라우저에서는 잘못된 입력, 저장 후 새로고침·이어하기, 건너뛰기, 추천이 분수 의미에서 덧셈으로 바뀌는 흐름, 시간 설정과 추천 이력을 점검한다.

실제 학습 효과·콘텐츠 전문가 검수는 아직 완료하지 않았다. 다음 단계는 새 진단/복습 문항 검수, 파일럿과 규칙 조정, 문항 풀 확대다. 세부 오개념별 보충·반복 복습·클래스 편집기·AI 생성은 별도 후속 범위다.
