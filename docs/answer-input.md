# 답안 입력

휴대폰에서 문제 아래 키패드가 펼쳐지면 문제와 입력란을 오가며 스크롤해야 했고, 간단한 숫자를 쓰는 데도 조작이 많았다. 앱/웹 구분보다 입력 장치와 화면 공간에 따라 입력기를 제공한다.

| 환경 | 정수·소수 | 분수 |
| --- | --- | --- |
| 휴대폰 | 기본 숫자 키보드 | 하단 고정 수식 패널 |
| 태블릿 터치 | 기본 숫자 키보드 | 중앙에 너비를 제한한 하단 패널, 가로 화면에서는 미리보기·제출과 키를 두 열로 배치 |
| 컴퓨터·외장 키보드 | 실제 키보드 | 입력란 근처의 작은 분수 도구와 실제 키보드 |

- `integer`는 `inputMode="numeric"`, 일반 `rational`은 `decimal`을 요청한다. 휴대폰마다 빠질 수 있는 음수 부호를 작은 보조 버튼으로 제공한다.
- 분수 표기가 필요한 `requiredForm` 문항은 터치 환경에서 패널을 바로 연다. 소수도 허용하는 문항에서는 기본 키보드를 우선하고 학습자가 「분수 입력」이나 「수식 키보드 열기」로 전환한다. 채점 정답을 보고 입력기를 선택하지 않는다.
- 패널은 문제 카드 밖의 화면 하단에 위치한다. `inputMode="none"`으로 시스템 키보드와 겹치지 않게 하고, 패널의 실제 높이와 safe area만큼 페이지 아래 공간을 확보한다. 화면 회전과 visual viewport 변화에 맞춰 위치·공간을 갱신한다. 짧은 문제는 입력란과 함께 보이도록 필요한 만큼만 스크롤하고, 긴 문제는 패널 위에서 스크롤할 수 있다.
- 작성 중인 답을 패널에서도 보여 준다. 선택 영역을 바꾸거나 커서를 이동해 일부만 고칠 수 있고, 분자·분모를 따로 선택할 수 있다. 답을 자동으로 약분하거나 계산하지 않으므로 형식 채점이 유지된다.
- 터치 여부는 `any-pointer: coarse`와 실제 포인터 입력으로 판단한다. 화면 너비만으로 태블릿을 컴퓨터로 분류하지 않는다. 패널이 열린 상태에서 실제 키보드의 문자·삭제 입력이 들어오면 해당 문항은 기본 입력으로 전환하며, 직접 다시 패널을 열 수도 있다.
- 제출 버튼은 입력란 옆 또는 패널 안 한 곳에만 표시한다. 제출·Escape·닫기·바깥 클릭 시 패널을 접는다. 수업, 문제집, 시작점 확인이 같은 입력 컴포넌트를 사용한다.

## 지원 범위

현재 답안/채점 규격은 `integer`, `rational`, `choice`뿐이다. 제곱이나 루트가 문제에 나온다고 수식 답안을 허용하는 것은 아니다. 예를 들어 제곱근을 묻더라도 현재 문항은 정수 답 또는 객관식으로 응답한다.

제곱·루트 입력은 아직 제공하지 않는다. 이를 제공하려면 답안 규격, 안전한 구문 해석, 동치 및 표기 형식 채점, 작성·발행 검증을 함께 확장해야 한다. 거부될 수식만 쓰게 하는 버튼을 현재 키패드에 추가하지 않는다.

## 확인 방법

UI 회귀 테스트는 기본 숫자 키보드 요청, 터치/데스크톱 선택, 분수 부분 편집, 외장 키보드 전환, 단일 제출, 패널 해제와 페이지 공간 정리를 확인한다. Chrome 기기 모의 실행으로 휴대폰 및 태블릿 세로·가로 배치, 가림·가로 넘침, 터치 제출과 실제 키 입력을 확인한다.

시스템 키보드의 실제 표시와 OS별 전환 애니메이션은 브라우저 모의 실행으로 검증되지 않는다. iOS Safari/앱과 Android Chrome/앱에서 정수·소수 입력, 기본 키보드↔분수 패널 전환, 회전, 닫기, 제출을 실기기로 확인해야 한다.
