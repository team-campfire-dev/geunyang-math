# 답안 입력

문제마다 입력기가 달라지면 다음 답을 쓰는 방법을 다시 찾아야 한다. 모든 주관식에서 분수·거듭제곱·제곱근·괄호와 같은 도구를 제공한다. 기기에 따라 배치만 달라지고 정답이나 문항 종류에 따라 키를 숨기지 않는다.

| 환경 | 입력 방식 |
| --- | --- |
| 휴대폰 | 답 칸을 누르면 화면 하단에 수식 키보드 |
| 태블릿 터치 | 너비를 제한한 하단 패널, 가로 화면은 수식·제출과 숫자 키를 두 열로 배치 |
| 컴퓨터·외장 키보드 | 입력란 근처의 같은 수식 도구와 실제 키보드 |

- 답 칸 자체에 수식을 그리며, 원문 문자열과 별도 미리보기를 함께 보여 주지 않는다. 하단 키보드는 편집 도구와 숫자 키만 담는다. 기본/외장 키보드도 같은 답 칸을 편집한다. 아직 수식으로 읽을 수 없는 입력이나 IME 조합 중에는 같은 칸에서 원문을 고칠 수 있다.
- 분자·분모, 밑·지수, 근호 안, 괄호 안의 네모칸을 눌러 직접 입력한다. 빈 칸은 점선, 선택한 칸은 강조색으로 표시한다. 숫자가 있는 칸을 누르면 해당 부분을 선택해 바꾸며, 화살표로 일부만 고칠 수 있다. 분수 안에 근호를 넣는 식으로 도구를 조합할 수 있다. 선택 범위와 커서를 수식 안에 표시하며, 화살표는 내부 직렬화 문자를 건너뛰고 숫자·칸·구조의 안팎을 이동한다.
- 실행 취소·다시 실행은 답과 선택한 칸을 함께 복원한다. Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl+Y도 지원한다. 새 편집은 이전 다시 실행 이력을 지우며, 다른 답이 외부에서 주어지면 이력을 초기화한다.
- 「구조 없애기」는 루트·괄호의 안쪽 값을 남긴다. 분수·거듭제곱은 분자/분모 또는 밑/지수 중 남길 값을 명시적으로 선택한다. 다른 부분을 실수로 없앴으면 실행 취소로 모두 되돌릴 수 있다.
- 입력 내용을 자동 약분하거나 계산하지 않는다. `(2)/(4)`는 그대로 서버에 보내 기약분수 표기 조건을 유지한다. 칸 시작에서 지우면 구조 기호를 지우지 않고 이전 칸으로 이동하며, 전체 지우기도 제공한다.
- 터치 패널은 `inputMode="none"`으로 시스템 키보드와 겹치지 않게 한다. 「기본 키보드」를 선택하거나 실제 키보드로 문자를 입력하면 패널을 접고 일반 텍스트 입력으로 전환한다. 선택은 같은 탭의 세션에 저장해 다음 문제에서도 유지한다. 수식 도구나 「수식 키보드 열기」로 돌아올 수 있다.
- 터치 여부는 `any-pointer: coarse`와 실제 포인터 입력으로 판단한다. 화면 너비만으로 태블릿을 컴퓨터로 분류하지 않는다.
- 패널은 문제 카드 밖에 위치한다. 실제 높이와 safe area만큼 페이지 아래 공간을 확보하고, 화면 회전과 visual viewport 변화에 맞춰 갱신한다. 짧은 문제는 입력란과 함께 보이도록 스크롤하며, 긴 문제는 패널 위에서 스크롤할 수 있다.
- 제출 버튼은 입력란 옆 또는 패널 안 한 곳에만 표시한다. 제출·Escape·닫기·바깥 클릭 시 패널을 접는다. 수업, 문제집, 시작점 확인이 같은 입력 컴포넌트를 사용한다.

## 제출 전 안내

빈 분모·지수·근호 안, 0인 분모, 음수의 제곱근, 미지원 지수는 해당 칸을 표시하고 이유를 설명한다. 「수정할 칸으로」나 제출 버튼을 누르면 문제 위치를 선택하며, 입력 오류는 서버로 제출하지 않는다. 버튼·Enter·일반 폼 제출에 같은 검사를 적용한다. 정수 답과 기약분수 조건은 답 칸 위에서 안내하고, 도구는 계속 동일하게 제공한다.

이 검사는 입력의 유효성만 확인한다. 기대 정답은 클라이언트에 없으며, 정오답과 기약분수 표기 채점은 서버에서 수행한다.

## 답안과 채점

`expression` 답안 규격을 추가했다. 작성 화면에서 `2^3`, `sqrt(2)` 같은 정답을 쓰면 수식 답안으로 저장하며, 숫자 정답도 「답 인정 범위」에서 수식으로 바꿀 수 있다. 저장·발행 검증과 학습 제출은 같은 구문 해석기를 사용한다. 학습 API에는 응답 종류만 보내고 정답 수식은 보내지 않는다.

지원하는 수식은 숫자·소수·분수·사칙연산·괄호·정수 지수·제곱근이다. 실제 키보드에서는 `sqrt(8)`, `√8`, `2^3`, `2(3+4)`도 쓸 수 있다. 제곱근은 근호 안을 계산한 값이 0 이상인 유리수여야 한다. `sqrt(sqrt(16))`은 되지만 `sqrt(1+sqrt(2))`는 아직 지원하지 않는다. 문자식·등식·복소수·분수 지수는 지원하지 않는다.

유리수 계수와 제곱 인수가 없는 근호들의 합으로 값을 정확히 비교한다. `sqrt(8)`과 `2sqrt(2)`, `1/(1+sqrt(2))`와 `sqrt(2)-1`은 같은 답이다. 근삿값에는 허용 오차를 적용하지 않는다. 예상 오답 이름표와 오답 집계도 같은 비교를 사용한다.

기존 `integer`는 정수로 쓴 답을 요구하고, `rational`은 같은 값의 수식을 받되 `requiredForm: reduced_fraction`이면 기약분수로 쓴 답만 인정한다. 편집기가 넣은 괄호는 표기이므로 `(1)/(2)`도 분수로 인정하지만 `sqrt(4)/4`는 기약분수로 쓴 답이 아니다. 입력기는 같아도 문제의 명시적인 표기 조건은 그대로 유지된다.

해석기는 사용자 코드를 실행하지 않는다. 입력 80자, 중첩 16단계, AST 96개 노드, 근호 항 32개, 지수 절댓값 32, 정수 크기 2,048비트, 연산 작업 20,000회로 제한한다. 빈 칸·0으로 나누기·음수의 제곱근·미지원 수식·제한 초과는 오답 대신 입력 오류로 안내한다. 기존 LaTeX 입력은 숫자로 된 분수 하나와 수식 감싸기만 변환하며 일반 LaTeX 수식 전체를 해석하지 않는다.

## 확인 방법

UI 테스트는 모든 주관식의 공통 도구, 단일 수식 답 칸, 각 구조의 칸 편집과 중첩, 실행 취소·다시 실행, 구조 제거, IME, 커서 이동, 오류 위치와 제출 차단, 키보드 선택 유지, 단일 제출과 패널 정리를 확인한다. 서버 통합 테스트는 수식 정답의 저장·발행·공개 응답·학습 제출을 확인한다. Chrome 기기 모의 실행으로 휴대폰·태블릿 세로/가로·컴퓨터의 배치, 가림, 넘침과 키 입력을 확인한다.

시스템 키보드의 실제 표시와 OS별 애니메이션은 브라우저 모의 실행으로 검증되지 않는다. iOS Safari/앱과 Android Chrome/앱에서 키보드 전환, 회전, 닫기, 제출을 실기기로 확인해야 한다.
