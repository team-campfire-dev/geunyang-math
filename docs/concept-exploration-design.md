# 개념을 따라 읽는 뜻풀이 — 설계와 구현

작성일: 2026-09-17 · 상태: **첫 구현 완료 / #48 main 반영·운영 배포 확인**. 코드 기준 `b8f635e`, [검증·배포 근거](deployment.md#개념-탐색-48).

대상: 수업을 읽다가 모르는 용어를 확인하는 학습자. 중등·고등·대학 수학에 같은 탐색 방식을 적용하되, 모든 개념을 같은 지식 수준에서 설명하려 하지 않는다. 아래 원칙에 맞춰 학습 화면·편집기·조회 API를 구현했다. 배포 상태와 구현 한계는 마지막 절에 구분한다.

## 1. 설명의 기준

**“누구에게나 쉬운 첫 설명” 대신 “이 수업이 전제하는 지식으로 정확하게 설명하기”를 기준으로 삼는다.** 처음부터 쉬운 말로 모든 개념을 정의할 수 있다는 가정은 버린다. 짧은 뜻풀이는 수업 전체를 대신하지 않는다.

개념은 독립적으로 이름을 붙이고 참조할 수 있는 단위다. 다른 개념 없이 설명할 수 있어야 한다는 뜻은 아니다. 「분수의 의미」는 수업명, 「분수」는 개념이며, 분수의 뜻풀이에서 정수나 나눗셈을 참조할 수 있다. 용어 사전도 선행 개념 없이 설명 가능한 원자성을 요구하지 않는 것으로 정리했다.

서로 다른 세 가지를 구분한다.

| 구분 | 예시 | 용도 |
|---|---|---|
| 개념의 정체성 | 분수, 도함수, 벡터 | 수업 분류와 개념 참조 |
| 뜻풀이의 맥락 | 전체를 나누는 분수, 실수 한 변수 함수의 도함수, 실수 좌표벡터 | 현재 수업에 맞는 설명 선택 |
| 수업의 선수 지식 | 이 수업은 함수와 극한을 알고 있다고 가정 | 수업 설계와 학습 경로 |

뜻풀이 안의 링크가 곧 선수 관계는 아니다. 관련 개념이나 예시도 링크할 수 있고, 서로 참조하는 설명도 가능하다. 이 링크들을 전역 선수 지식 트리로 자동 변환하지 않는다.

학교급은 설명을 고르는 단독 기준으로 쓰지 않는다. 같은 대학생도 미적분은 익숙하고 선형대수는 처음일 수 있다. “초급 / 중급 / 고급” 세 종류를 모든 개념에 강제로 만들지 않는다.

## 2. 학습자 화면

화면 명칭은 **개념 뜻풀이**다. 화면에는 개념명과 뜻을 보여 주며, “nested tooltip” 같은 구현 용어는 드러내지 않는다.

1. 본문의 밑줄 친 개념을 클릭·탭하거나 키보드로 실행한다.
2. 뜻풀이 패널 하나가 열린다. 본문 위치와 입력하던 답은 유지한다.
3. 뜻풀이 속 다른 개념을 누르면 같은 패널의 내용이 바뀐다.
4. `← 분수`처럼 바로 전 개념으로 돌아가는 버튼을 제공한다.
5. `수업으로 돌아가기`는 깊이에 관계없이 패널을 닫고 최초 위치로 돌아간다.

경로 예시: `수업 → 분수 → 정수 → 수업으로 돌아가기`.

창을 겹겹이 띄우지 않는다. hover는 필수 동작에 사용하지 않는다. PC와 터치 기기 모두 같은 탐색 모델을 쓴다.

### 패널 구성

| 위치 | 내용 | 작성 기준 |
|---|---|---|
| 상단 | 이전 개념, 수업으로 돌아가기 | 항상 찾을 수 있게 유지 |
| 제목 아래 | 설명의 맥락 | 예: `실수 한 변수 함수에서`. 맥락이 뜻을 제한한다면 생략하지 않음 |
| 첫 내용 | 현재 맥락의 뜻 | 한 문장이나 글자 수를 강제하지 않음. 필요한 수학적 조건을 보존 |
| 다음 내용 | 예시·그림·직관 | 필요할 때만. 예시를 일반 정의처럼 제시하지 않음 |
| 본문 안 | 다른 개념으로 가는 링크 | 작성자가 필요한 곳에 명시적으로 지정 |
| 하단 | 관련 수업 | 실제 연결할 수업이 있을 때만 제공 |

“쉽게 / 정확하게”처럼 정확도를 난이도와 맞바꾸는 탭은 쓰지 않는다. 형식적 정의가 필요한 수업에서는 그 정의가 첫 내용이어도 된다. 설명이 길면 세부 설명을 접을 수 있지만, 정의의 적용 범위나 필수 조건을 접힌 영역에만 넣지 않는다.

관련 수업을 눌렀을 때는 먼저 수업명과 다루는 내용을 보여 준다. 사용자가 시작을 선택하면 이동하고, 원래 수업의 위치와 답안 초안으로 돌아올 수 있게 한다. 깊게 탐색했다고 자동으로 보충 수업에 보내지 않는다.

### 화면 크기와 접근성

- 넓은 화면: 본문을 읽을 공간이 남는 경우 옆 패널. 비모달 영역으로 취급하고 본문과 패널을 모두 조작할 수 있게 한다.
- 좁은 화면: 같은 내용을 하단에서 열리는 모달 시트로 표시한다. 긴 수식과 설명을 읽을 만큼 확장할 수 있게 하고, 헤더와 닫기 동작은 유지한다.
- 패널 너비가 아니라 본문의 남는 폭을 기준으로 배치를 전환한다. 실제 수식과 확대 글꼴로 임계값을 검증한다.
- 열면 패널 제목으로 초점을 이동하고, 이전 개념으로 돌아오면 이전 읽기 위치를 복원한다. 닫으면 최초 본문 용어로 초점을 돌린다.
- 모바일 모달은 배경을 비활성화하고 초점을 내부에 가둔다. PC 비모달 패널에는 `aria-modal`이나 모달 초점 가두기를 적용하지 않는다.
- 화면 내 뒤로 버튼은 개념 한 단계, `Escape`는 탐색 전체 닫기다. 브라우저/기기 뒤로 가기도 열린 탐색을 한 단계 되돌리도록 경로 상태와 연동한다. 닫힌 뒤에야 원래 페이지 이동을 처리한다.
- 제목 변경을 보조기기에 전달하되 본문 전체를 매번 live region으로 읽히지 않는다. 색 외에도 밑줄과 명확한 버튼 이름으로 링크를 구분한다.

참고: WAI-ARIA APG의 [tooltip 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/)은 tooltip 안의 초점 가능한 상호작용을 다루는 패턴이 아니다. 모바일 모달의 초점·닫기 동작은 [dialog 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)을 참고한다. 패널은 원래 수업으로 복귀하면서 개념을 따라 읽는 제품 요구에 맞춰 선택했다.

## 3. 중등부터 대학까지의 콘텐츠 예시

다음은 화면과 작성 규칙을 검토하기 위한 예시이며 실제 발행 원고는 수학 내용 검토를 거친다.

### 분수: 전체를 같은 크기로 나누는 수업

첫 설명 예시:

> 이 수업에서는 전체를 같은 크기로 나눈 것 중 얼마만큼인지를 분수로 나타냅니다. 3/4는 전체를 4등분한 것 중 3개만큼입니다.

이 설명의 맥락은 반드시 표시한다. 이것으로 음수·가분수·대수적 분수까지 모두 정의했다고 주장하지 않는다. 이 맥락에서 불필요한 “정수”를 억지로 첫 문장에 넣을 이유도 없다.

공통 사전의 수에 관한 설명을 선택했다면 다음처럼 쓸 수 있다.

> 분수는 여기서 a/b 꼴로 수를 나타낸 표현을 말합니다. a와 b는 정수이고 b는 0이 아닙니다.

이 경우 `정수`를 따라 읽을 수 있게 한다. 같은 개념의 설명이라도 현재 수업이 무엇을 하려는지에 따라 진입점이 달라진다. 학습자가 어려워 보인다는 추정만으로 두 설명을 자동 교체하지 않는다.

### 도함수: 실수 한 변수 미적분

첫 설명 예시:

> 열린 구간에서 정의된 실수값 함수 f에 대해, 각 점 x에서 차분몫 (f(x+h)−f(x))/h의 유한한 극한이 존재할 때 그 값을 f′(x)로 둡니다. 이 구간에서 f′를 f의 도함수라고 합니다.

`함수`, `극한`, `차분몫` 중 작성자가 필요한 개념에 링크를 단다. “순간 변화율”은 직관을 돕는 해석으로 함께 둘 수 있지만, 그것만으로 정의를 대체하지 않는다. 차분몫에서는 h≠0이고 극한을 취할 때 h가 0으로 가까워진다는 조건을 유지한다.

극한의 뜻풀이를 읽어도 이해되지 않는 사람에게는 극한을 다루는 관련 수업이 필요할 수 있다. 용어를 끝없이 펼치면 결국 누구나 이해하게 된다는 약속은 하지 않는다.

### 벡터: 좌표 계산과 추상 선형대수

좌표 계산 수업에서는 “이 수업의 벡터는 실수를 순서대로 나열한 (x, y) 또는 (x, y, z)로 다룹니다”처럼 범위를 한정할 수 있다. 추상 선형대수 수업에서는 “벡터공간의 원소를 벡터라고 부릅니다”가 적절한 진입점일 수 있다. 후자는 단독으로 충분한 설명이 아니므로 벡터공간과 스칼라로 연결한다.

실수 벡터공간과 복소수 벡터공간에서는 스칼라의 설명도 달라진다. 대학 수업에서 `스칼라`를 눌렀는데 무조건 “실수”라고 설명하는 공통 뜻풀이로 떨어지면 안 된다. 링크가 가리키는 설명의 맥락까지 작성 시 확인한다.

같은 이름이라는 이유로 별개의 수학 대상을 병합하지 않는다. 예를 들어 다항식의 차수와 미분방정식의 차수는 구별된 개념으로 관리할 수 있다. 반대로 예시와 표현 방식만 다르면 뜻풀이를 나누고 개념의 정체성은 유지한다. 벡터처럼 특수한 경우와 일반화의 관계는 개념 편집 기준에서 검토한다. 이를 뜻풀이 UI가 자동 판단하지 않는다.

**개념을 공유한다고 숙련도까지 동일하다는 뜻은 아니다.** 좌표벡터 연산 경험이 추상 벡터공간의 이해를 보장하지 않는다. 기존 전역 준비도를 대학 수학까지 그대로 이전할 수 있는지는 별도 개인화 설계 과제로 남긴다. 이번 기능은 그 이전을 새로 확대하지 않는다.

## 4. 연결과 탐색 규칙

### 설명 선택

- 읽는 순간 난이도를 추정해 설명을 바꾸지 않는다. 작성자가 링크마다 개념과 뜻풀이 범위를 선택한다.
- 기존 `DefinitionRef`의 개념 키와 범위 식별을 유지한다. 같은 개념의 수업용 설명과 공통 설명을 구별한다.
- 뜻풀이 안의 링크도 특정 설명을 가리킨다. 자식 링크를 현재 수업 범위로 무조건 덮어쓰지 않는다.
- 편집기는 현재 수업 뜻풀이를 먼저 제안하고 공통 사전을 함께 찾게 한다. 제안 순서는 작성 편의이며, 최종 참조는 명시적으로 저장한다.
- 공통 뜻풀이가 특정 수업의 비공개 설명에 의존하지 않게 한다. 좁은 범위로만 제공 가능한 연결은 그 범위의 뜻풀이에 작성한다.
- 맞는 설명이 없으면 새 뜻풀이를 작성하거나 링크 없이 출판한다. 뜻이 달라지는 설명으로 조용히 대체하지 않는다.

현재 저장 구조에는 코스·조직 범위도 있지만 편집기는 공통·현재 수업 중심이다. 첫 구현은 이 두 범위로 시작하고, 코스에서 재사용하는 뜻풀이 편집은 후속 확장으로 둔다. 모든 개념에 여러 설명을 미리 작성할 필요는 없다.

### 순환·오류·긴 경로

| 상황 | 동작 |
|---|---|
| A → B → A | 같은 뜻풀이 식별자가 경로에 있으면 그 위치로 돌아가 이후 경로를 접음. 패널을 추가 생성하지 않음 |
| 같은 개념, 다른 범위 설명 | 다른 뜻풀이로 취급. 제목 아래 맥락으로 차이를 드러냄 |
| 깊은 탐색 | 임의의 의미상 깊이 제한은 두지 않음. 이전 개념과 수업 복귀는 항상 제공. 긴 경로 표시는 축약 |
| 로딩 | 직전 내용과 복귀 동작을 유지하면서 해당 이동의 진행 상태 표시 |
| 불러오기 실패 | 직전 내용 유지, 재시도 제공. 실패한 항목은 탐색 기록에 넣지 않음 |
| 설명 삭제·권한 없음 | 사용할 수 없다는 상태와 돌아가기 제공. 다른 의미의 설명으로 자동 대체하지 않음 |
| 빠른 연속 클릭 | 마지막으로 선택한 이동만 반영. 늦게 온 응답이 현재 내용을 덮어쓰지 않음 |
| 닫았다 다시 열기 | 본문에서 누른 개념을 새 탐색의 시작점으로 삼음 |
| 패널이 열린 동안 다른 본문 개념 선택 | 새 본문 용어에서 탐색을 시작. 이전 개념 탐색과 수업 위치는 혼동하지 않음 |

개념 그래프 전체를 재귀적으로 펼치거나 선행 로딩하지 않는다. 선택한 설명 하나와 직접 연결된 참조 정보만 읽고, 다음 설명은 선택할 때 가져온다. 동일 방문 내용은 읽기 세션 동안 재사용하되 접근 정책은 요청마다 검증한다.

## 5. 작성자 경험

1. 개념을 만들거나 선택한다. 예: `도함수`.
2. 공통 또는 현재 수업 뜻풀이를 선택한다.
3. 필요한 경우 “이 설명의 맥락”을 적는다. 예: `실수 한 변수 함수, 열린 구간`.
4. 뜻·조건·예시를 쓰고, 필요한 낱말에 개념 링크를 단다. 모든 명사에 자동 밑줄을 긋지 않는다.
5. 학습자 미리보기에서 링크를 따라가며 선택된 맥락이 맞는지 확인한다.

검증은 링크 존재, 범위 접근 가능성, 필수 본문 유무를 확인한다. 필수 수학 조건의 정확성은 콘텐츠 검토가 담당한다. “쉬운 단어 비율”이나 학교급만으로 통과 여부를 결정하지 않는다.

순환 참조는 일괄 금지하지 않는다. 이번 구현에서는 미리보기 안내와 방문 경로 복귀를 제공하며, 실제 순환 목록을 찾아 경고하는 기능은 후속 범위다. 다만 설명 없이 A를 B로, B를 A로 바꿔 말하기만 하는 원고는 고친다. 기술적으로 순환을 처리하는 것과 교육적으로 설명이 충분한 것은 별개다.

## 6. 구현 위치

관련 구현:

- `src/shared/rich-text.ts`: 기존 참조 식별을 재사용. 글에 보이는 표현과 개념명은 구별 유지.
- `src/features/learning/content-blocks.tsx`: 문단의 열린 상태를 화면 수준 탐색기로 옮김. 정의 안의 링크도 같은 탐색기로 연결.
- `src/core/content.ts`: 정의의 링크 블록 허용 및 직렬화 계약. 문제집이나 불필요한 상호작용 블록까지 허용하지 않음.
- `src/core/content-bundle.ts`: 연결의 범위 검증과 문제 영역의 설명 제한 검토.
- `src/core/glossary.ts`: 첫 관련 수업을 자동 선택하던 규칙 개선.
- 정의 저장/API/편집기: 설명 맥락, 정의 간 참조, 지연 조회와 오류 상태. 웹·모바일 소비자가 같은 계약을 처리하는지 확인.

뜻풀이가 변경 가능한 기존 정책은 유지하되, 열어 둔 탐색의 방문 항목은 응답 시점의 내용과 revision을 보관해 뒤로 가기에서 문장이 갑자기 바뀌지 않게 한다. 새 탐색은 최신 설명을 읽는다. 새 정의를 요청할 때 서버가 현재 수업 판본과 연결 경로를 검증한다. 로컬 뒤로 가기는 이미 받은 내용을 복원하므로 재조회하지 않는다. 캐시는 계정·수업 판본·활동을 바꾸면 폐기한다.

## 7. 문제·진단에서의 경계

기존 검증은 문제에서 직접 평가하는 개념의 뜻풀이 연결을 막는다. A의 뜻풀이에서 평가 개념 B로 들어갈 수 있게 하면 직접 연결 검사만으로는 이 규칙이 유지되지 않는다. 뜻풀이가 발행 후 수정될 수 있어 발행 시 검사만으로도 부족하다.

**첫 구현은 수업의 설명·예시·정리 본문에 적용한다.** 문제 지문·힌트·해설·과제에서는 단일 단계 뜻풀이를 유지하고 추가 개념 탐색은 제공하지 않는다. 진단에는 뜻풀이 자체를 제공하지 않는다. 같은 공유 정의라도 호출된 화면의 정책에 따라 탐색 가능성이 달라진다. 링크 제거는 화면에서만 하지 않고 서버의 제공 범위에도 반영한다.

문제 영역으로 확대할 때는 현재 평가에서 열람 가능한 정의를 서버가 매 요청 판단해야 한다. 차단 대상 정의 본문을 미리 보내 두거나, 수업 탐색 캐시가 문제에서 재사용되게 하지 않는다. 연결된 설명 자체가 답을 말해 주는지는 개념 키 차단만으로 판정할 수 없으므로 콘텐츠 검토도 필요하다.

첫 구현에서 뜻풀이 열람은 학습 완료·오답·힌트 사용·준비도 변화의 근거로 삼지 않는다. 탐색이 길었다는 사실만으로 선행 지식 부족을 판정하지 않는다.

## 8. 첫 구현 범위와 검증 목표

첫 구현에 포함: 본문에서 시작하는 공유 패널, 이전 개념/수업 복귀, 정의 안의 링크 작성, 공통/수업 범위 선택, 맥락 표시, 순환 처리, 키보드·모바일 조작, 문제 영역의 탐색 제한.

편집기의 「개념으로 찾기」는 이미 개념별 뜻풀이와 관련 수업을 모아 보여준다. 후속 검토는 학습자용 독립 개념 탐색, 코스 뜻풀이 편집, 관련 수업 선택 개선, 대학 수학에서의 준비도 이전이다. AI 자동 단순화나 개인별 자동 설명 교체는 첫 구현에 포함하지 않는다.

다음 흐름을 검증 목표로 삼는다. 실제 수행한 검증과 남은 검수는 9절에 구분한다.

1. 분수 → 정수 → 이전 → 수업 복귀 후 스크롤과 입력 중이던 답이 유지된다.
2. 도함수 → 극한을 열어도 원래 정의의 조건과 수식이 누락되지 않는다.
3. 좌표벡터 수업과 추상 선형대수 수업이 서로 맞는 뜻풀이로 연결된다. 복소수 맥락의 스칼라를 실수로 바꾸어 설명하지 않는다.
4. A → B → A가 반복 패널이나 무한 요청을 만들지 않는다.
5. 같은 개념의 서로 다른 범위 설명을 정확히 구별한다.
6. 재시도·삭제·권한 변경·늦은 응답 상황에서도 돌아갈 경로가 유지된다.
7. 320px 폭, 글꼴 확대, 긴 한국어 용어와 수식에서 조작 요소가 겹치지 않는다.
8. 키보드만으로 열기·연결·뒤로·닫기를 수행한다. 모달과 비모달 각각의 초점 처리를 확인한다.
9. 문제에서 열람이 금지된 개념을 간접 링크나 이전 수업 캐시로 읽을 수 없다.
10. 정의를 열거나 오래 탐색해도 준비도와 문제 판정 기록이 바뀌지 않는다.

사용성 검토에서는 “용어를 얼마나 많이 눌렀나”보다, 필요한 뜻을 확인한 뒤 원래 문장을 이어 읽을 수 있는지와 설명의 적용 범위를 오해하지 않는지를 본다. 중등·고등·대학 수준의 실제 원고로 각각 확인한다.


## 9. 첫 구현의 구체적인 경계

- `POST /api/v1/definitions`는 현재 수강 판본(미수강자는 최신 발행 판본)의 설명·예시·정리에서 출발한 경로인지, 각 연결이 지금도 존재하며 같은 수업 또는 공통 사전 범위인지 확인한다. 선택한 정의 하나만 반환한다. 요청 자원 제한은 경로 128개·본문 64 KB이며 학습 난이도를 판단하는 제한이 아니다.
- 기존 수업·과제 응답에는 연결을 제거한 뜻풀이를 제공한다. 문제 렌더러는 탐색 콜백을 받지 않고 현재 평가 개념도 제외한다. 진단은 뜻풀이를 제공하지 않는다.
- 관련 수업은 현재 코스에서 같은 개념을 다루는 첫 수업으로 한정한다. 이름과 요약을 확인한 뒤 새 탭에서 열어 현재 수업의 위치와 답안을 보존한다. 수업 추천 순위는 후속 범위다.
- 뜻풀이 편집기는 맥락·요약·본문과 `@` 연결을 제공한다. 공통 사전은 작성자도 연결을 위해 읽을 수 있고 저장은 관리자만 가능하다. 편집 중인 원고를 공유 탐색기로 미리 볼 수 있다. 순환은 저장을 금지하지 않으며 작성자에게 서로를 가리키기만 하는 설명인지 미리보기로 확인하도록 안내한다. 자동 순환 목록 경고는 아직 없다.
- 넓은 학습 화면에서는 옆 패널, 좁은 화면과 뜻풀이 편집 미리보기에서는 모달 시트를 사용한다. 뒤로 가기에서 방문한 본문과 내부 스크롤을 복원하고, 닫으면 본문 용어의 포커스와 페이지 위치를 복원한다. 본문의 다른 용어를 누르면 이전 탐색의 브라우저 기록을 정리하고 새 경로를 시작한다.
- 기본 사전은 `glossary-v3.json`으로 분수→정수 등 연결과 맥락을 보강했다. 정수·공약수·기약분수를 추가해 공통 뜻풀이는 10개다. 중등 분수 콘텐츠를 설치하며, 고등·대학 수학 예시는 설계 검토용이다. 그 수준의 실제 원고·학습 효과 검증은 완료했다고 주장하지 않는다.

실제 배포는 새 앱·migrator 이미지를 빌드한 뒤 `db:migrate → db:seed → content:publish → content:verify → 새 앱 기동` 순서다. migrator는 새 코드로 nullable `usageNote` migration과 사전 v3를 함께 처리한다. 새 앱이 뜨기 전에는 이전 서버가 새 `@3` 뜻풀이를 읽게 되는 짧은 구간이 있으므로 호환성을 고려해야 한다. 기존 `glossary-v2.json`과 적용 원장은 수정하지 않는다. v3는 해당 공통 사전 10개를 한 번 갱신하므로 운영에서 별도로 고친 사전이 있다면 배포 전에 비교한다. 새 `@3` 뜻풀이를 이해하지 못하는 이전 서버로 되돌릴 때는 콘텐츠 호환성도 확인해야 한다.
