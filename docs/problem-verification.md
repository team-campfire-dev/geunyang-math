# 문제 검증기

2026-10-02 작성 · 코드: [`src/core/verify/`](../src/core/verify) · 검사: [`tests/problem-verifier.test.ts`](../tests/problem-verifier.test.ts)

AI가 만든 문제를 발행하기 전에, **정답 키·보기·예상 오답이 문제가 묻는 계산과 맞는지** 서버가 직접 계산해 확인한다. 2026-10-16부터 편집 화면의 「AI로 문제 만들기」가 이 검사를 거친 문제만 내놓는다(아래 [생성 흐름](#생성-흐름)).

## 왜 필요한가

2026-10-01에 경량 모델 셋(GPT Instant, Claude Sonnet 5.5 low, Gemini 3.6 Flash)에게 같은 요청으로 오답 기반 문제를 만들게 했다. 36문제 중 **35개는 정답이 맞았고 1개가 틀렸다**. GPT가 $\frac{3}{4}+\frac{2}{9}$의 정답 키를 보기 b($\frac{29}{36}$)로 찍었고, 보기 넷 어디에도 실제 답 $\frac{35}{36}$이 없었다. 해설은 쓰다가 스스로 「보기에는 정답이 없어요」라고 적었다. 그대로 나갔다면 맞게 푼 학습자가 전부 틀린 것으로 기록된다.

정답 키 오류는 드물지만, 나가면 **오답 기록 자체가 오염된다**. 그래서 모델이 문제와 함께 「이 문제가 묻는 계산」(이하 **주장**, `solves`)을 내게 하고, 서버가 그 계산을 해서 나머지를 대조한다.

| 날짜 | 시험 | 결과 |
|---|---|---|
| 2026-10-01 | 모델 셋 × 사례 둘(이항 부호, 분모끼리 더하기), 주장 없이 | 36문제 중 정답 키 오류 1(GPT), 입력 칸이 거부하는 예상 오답 1(Sonnet). 둘 다 이 검증기가 거부한다(검사 파일의 고정 사례) |
| 2026-10-02 | 같은 두 사례를 주장과 함께(v2 프롬프트), Sonnet 5.5 낮음 | 12문제 모두 `verified`(정확). 경고 없음 |
| 2026-10-02 | 같은 두 사례, v3 프롬프트(작성 지침 반영), Sonnet 5.5 낮음. 다른 대화에서 지문만 주고 독립 풀이 | 12문제 모두 `verified`, 독립 풀이 12개 모두 정답 키와 일치 |
| 2026-10-16 | 판단을 묻는 실수 넷(소수 판별, 정수 분류, 무리수 판별, 대소 비교) 각 6문제 | 24문제 중 17개 통과. 걸린 7개 중 5개가 「소수인 것은?」처럼 **값인 보기에 성질을 묻는** 문제였고(주장으로 쓸 방법이 없었다), 순환소수 보기를 읽지 못했고, 문장 보기의 잘못된 계산을 값으로 계산하려다 미확인이 됐다. `property`·판정 함수·순환소수를 더하고 순서를 고친 뒤 같은 요청으로 **24문제 중 22개** — 남은 둘은 따로 푼 쪽의 실수(미확인)와 닿지 않는 오답 계산(틀림)이다 |
| 2026-10-16 | [생성 흐름](#생성-흐름)으로 처음 실제 호출. 분수의 덧셈(분모끼리 더하기)과 일차방정식(이항 부호, 곱한 수를 이항) 각 6문제 | 정답 키는 모두 맞았다. 걸린 것은 **지어낸 예상 오답**이었다 — 잘못된 계산이 그 값에 닿지 않음, 같은 값에 이름 둘, 정수 답 문제의 분수 오답, 설명문이 된 보기. 일차방정식에서 writer effort `low`는 30문제 중 16개, `medium`은 25문제 중 25개가 통과해 `medium`으로 정했다(출력 약 1.7배). 그 밖에 응답 하나가 해설 안에서 다음 문제를 시작했고(`},{`), 「$\frac{5}{12}$판」의 「판」을 단위로 읽지 못했다 — 둘 다 고쳤다 |

생성 프롬프트에서 배운 쓰기 규칙은 [작성 지침](lesson-writing-guide.md) §4·§10과 그 피드백 기록에 쌓았다.

## 판정

| 판정 | 뜻 |
|---|---|
| `verified` | 모든 검사를 통과했다 |
| `rejected` | 어떤 검사가 **확실히** 실패했다. 문제가 틀렸다 |
| `unverified` | 검사기가 판단하지 못했다. **통과가 아니다** |

판정은 일부러 한쪽으로 기운다. 판단하지 못한 것은 통과시키지 않는다. 읽을 수 없는 보기가 하나라도 있으면, 나머지가 다 맞아도 `unverified`다(그 보기도 정답일 수 있으므로).

`verified`에는 근거의 강도가 붙는다.

| 강도 | 근거 |
|---|---|
| `exact` | 처음부터 끝까지 유리수로 정확히 계산했다. 분수·거듭제곱·경우의 수 같은 학교 계산 대부분이 여기다 |
| `sampled` | 식이 모든 값에서 같은지를 서로 다른 12개의 유리수 점에서 확인했다(항등식, 식으로 된 보기) |
| `numeric` | 무리수·원주율·삼각함수가 끼어 부동소수점으로 계산했고, 10억분의 1 안에서 일치했다 |
| `estimated` | 적분·극한·구간 탐색처럼 수치로 어림했고, 100만분의 1 안에서 일치했다(구간 탐색으로 찾은 해의 목록도 같은 기준) |

부동소수점이 답을 가르지 못하는 곳에서는 짐작하지 않고 `unverified`로 남긴다. 무리수 계수의 6중근처럼 반올림 오차 안에서 근이 몇 개인지 갈리지 않는 경우, 정수 근처의 `floor`, 0 근처의 `sign`이 그렇다.

## 주장의 종류

주장은 JSON 하나다. 식은 계산기 문법으로 쓴다(아래 「식 문법」).

| `kind` | 언제 | 예 |
|---|---|---|
| `value` | 값 하나를 계산하는 문제 | `{"kind":"value","expression":"3/4 + 2/9"}` |
| `solve` | 방정식(연립 포함)의 해 | `{"kind":"solve","equation":"x^2 - 5x + 6 = 0","unknown":"x","select":"largest"}` |
| `inequality` | 부등식의 해, 또는 그 안의 정수 | `{"kind":"inequality","inequality":"2x - 3 < 7","variable":"x","select":"count","among":"naturals"}` |
| `integral` | 정적분. 부정적분을 함께 내면 정확해진다 | `{"kind":"integral","integrand":"3x^2","variable":"x","from":"0","to":"2","antiderivative":"x^3"}` |
| `expression` | 보기가 식인 문제(대입한 식, 전개한 식) | `{"kind":"expression","expression":"3(x - 2)","variables":["x"]}` |
| `choose` | 「옳은 것은?」「옳지 않은 것은?」(보기가 문장) | `{"kind":"choose","which":"true"}` |
| `choose` + `property` | 「소수인 것은?」「무리수가 아닌 것은?」(보기가 값) | `{"kind":"choose","which":"true","property":"isprime(x)"}` |

모든 종류에 공통으로 `given`(상수의 값, `{"a":"3"}`)과 `define`(문제가 정의한 함수, `{"f(x)":"x^2+1"}`)을 붙일 수 있다.

**`solve`의 `select`** — `unique`(기본, 해가 정확히 하나여야 한다), `all`, `largest`, `smallest`, `positive`, `negative`, `sum`, `product`, `count`. `sum`·`product`는 중근을 겹친 만큼 센다(근과 계수의 관계와 같게). `count`는 서로 다른 해의 개수다. 미지수가 둘 이상이면 `ask`로 무엇을 계산할지 쓴다(`"ask":"x*y"`). 삼각·지수·로그방정식은 `where`로 구간을 줘야 한다(`"where":"0 <= x < 2pi"`). `domain:"complex"`면 허근도 해다.

**`property`** 는 보기 하나의 값을 `x`에 넣어 1(만족) 또는 0이 되는 식이다. 보기는 값이어야 한다(`$17$`, `$x=\sqrt{7}$`, `$0.\dot{3}$`). `which: "true"`면 만족하는 보기가 정확히 하나여야 하고, `"false"`면 만족하지 않는 보기가 정확히 하나여야 한다. 판정 함수(아래 「식 문법」)를 산술로 묶어 쓴다 — 「무리수인 것」은 `1 - isrational(x)`, 「합성수인 것」은 `isnatural(x - 1) * (1 - isprime(x))`.

**검증은 푸는 것보다 쉽다.** 부정적분은 서버가 구하지 않는다. 모델이 낸 부정적분을 미분해 피적분함수와 같은지 보고, 그 차를 수치 적분과 다시 대조한다. 둘이 어긋나면 부정적분이 구간 안에서 끊긴 것이다($\int\frac{dx}{2+\cos x}$의 $\arctan(\tan\frac x2)$ 꼴은 $x=\pi$에서 뛴다). 이때는 수치 적분값을 쓰고 `claim-note`로 남긴다. 피적분함수가 구간 안에서 정의되지 않으면 수치 적분 자체가 실패해 미확인이 된다.

## 보기를 읽는 법

보기는 쓰인 그대로 읽는다. 읽을 수 있는 것:

- 값: `$\frac{5}{13}$`, `$x=-3$`, `$3$개`, `12 cm`, `$25\%$`, `$2\frac{1}{3}$`(대분수, `2\,\frac13`처럼 띄어 써도), 순환소수 `$0.\dot{3}$`·`$0.\dot{1}\dot{4}$`·`$0.1\dot{2}$`·`$0.\overline{12}$`(정확한 분수로) — 끝에 붙은 단위는 값이 아니다. 보기마다 단위가 다르면 `option-units`
- 해의 목록: `$x=2$ 또는 $x=3$`, `$x=1\pm\sqrt{2}$`, `$x=-100,100$`
- 해집합: `$x \le -4$ 또는 $x \ge -1$`, `$-4 \le x \le -1$`, `해가 없다`, `모든 실수` — 마지막 둘은 보기 전체가 그 말일 때만이다. `모든 실수 (단, $x \neq 3$)`처럼 덧붙인 말이 있으면 읽지 않는다
- 참·거짓을 가릴 문장: `$\frac12+\frac13=\frac56$`, `$(a+b)^2=a^2+2ab+b^2$`(항등식), `$x+3=7 \Rightarrow x=7-3$`(풀이 한 단계)
- 식: `$3(x-2)$`, `$y = 3x - 6$`

말로 된 보기(「기울기가 같다」, 「절반보다 크다」)와 모르는 LaTeX 명령은 읽지 않는다. 읽지 못한 보기는 추측하지 않고 `option-unreadable`로 보고한다. 다음도 일부러 읽지 않는다.

- 단위가 든 문장: `$1\,\text{m} = 100\,\text{cm}$`, `$1m = 100cm$`(수식 안의 `m`, `cm`을 변수로 읽으면 거짓이 된다)
- 순서쌍과 좌표: `$x=1, y=2$`, `$(0,100)$` — 두 미지수의 값을 한 미지수의 값 목록으로 읽지 않는다
- 쉼표 천 단위는 수 하나만 있을 때만 붙인다: `$1,000$`은 1000이고, `$x=-100,100$`은 두 값이다

**문장의 참·거짓은 이렇게 가린다.**

- 문자가 없는 문장은 계산한다. 문자가 하나인 부등식(「모든 $x$에 대해 $x^2-2x+1>0$」)은 해집합을 구해 정확히 가린다 — 표본으로 가리지 않는다.
- 문자가 든 등식은 항등식인지를 표본 점에서 본다. 한쪽만 정의되는 점은 반례다: $\log_2 x^2 = 2\log_2 x$는 $x=-1$에서 왼쪽만 정의되므로 거짓이다.
- `⇒`는 해집합으로 본다. 두 해집합이 같으면 옳은 단계이고, 왼쪽이 오른쪽에 들어가지 않으면 틀린 단계다. 왼쪽이 오른쪽에 진부분집합으로 들어가면(「$x=3 \Rightarrow x^2=9$」) 명제로는 참이지만 풀이 단계로는 틀리므로 미확인으로 남긴다.

## 식 문법

계산기처럼 쓴다. 코드로 실행되지 않는 유한한 문법이고, 길이(400자)·깊이·계산량에 상한이 있다.

- 사칙연산과 거듭제곱: `+ - * / ^`. 곱셈 기호는 생략할 수 있다(`2x`, `3(x-1)`, `(x+1)(x-1)`, `2sqrt(3)`). 숫자 바로 뒤의 숫자는 거부한다(`x 2`).
- `-x^2`는 $-(x^2)$이고 `2^3^2`는 $2^9$다.
- 함수는 반드시 괄호와 함께: `sqrt cbrt root(x, n) abs exp ln log(x) log(b, x) sin cos tan sec csc cot asin acos atan sinh cosh tanh floor ceil round sign min max gcd lcm mod`
- 경우의 수: `n!`, `factorial(n)`, `nCr(n, r)`, `nPr(n, r)`, `nHr(n, r)`
- 통계: `mean median var sd`(모집단), `svar ssd`(표본, 대학 통계)
- 판정: `isprime isinteger isnatural iseven isodd isrational` — 참이면 1, 거짓이면 0이라 셀 수 있다(`sum(isprime(k), k, 1, 10)`은 4). 짐작하지 않는다: 부동소수로만 계산된 값은 반올림이 가를 수 없을 만큼 정수에서 멀 때만 「정수가 아니다」라고 하고, `isrational`은 **식의 모양이 무리수임을 보일 때만** 0이다 — π·e, 완전거듭제곱이 아닌 유리수의 거듭제곱근, 거기에 유리수를 더하거나 0 아닌 유리수를 곱하거나 나눈 것. $\sqrt2\cdot\sqrt2$, $\sqrt2+\sqrt3$처럼 모양이 증명하지 못하면 `unstable`로 실패한다(미확인).
- 미적분: `diff(f, x, a)`(a에서의 미분계수), `diff(f, x, a, n)`(n계), `integral(f, x, a, b)`, `limit(f, x, a)`(양쪽), `limit(f, x, a, 1)`(오른쪽), `limit(f, x, inf)`, `sum(f, k, a, b)`, `prod(f, k, a, b)`
- 상수: `pi`, `e`, `i`. 주장이 그 이름을 변수로 쓰면(`sum(i^2, i, 1, 3)`) 변수가 이긴다.
- 각도: `30°`는 어디서나 각 $\frac{\pi}{6}$이다(`given`, `define`, `where`, `ask` 안에서도). 그래서 `180° = pi`는 참이고, 보기 `$60^\circ$`와 `$\frac{\pi}{3}$`는 같은 값이라 둘 다 있으면 `choice-ambiguous`다. 도로 센 수를 답으로 묻는 문제는 주장을 `°` 없이 쓴다(`180 - 50 - 60`).
- 관계: `= < <= > >= !=`, 이어 쓰기 `0 <= x < 2pi`. 절댓값 `|x - 1|`. 아래첨자 `x_1`.

학교의 관례를 따른다: $\sqrt{-4}=2i$, $\sqrt{-2}\sqrt{-3}=-\sqrt6$, $(-8)^{1/3}=-2$(음수의 홀수 제곱근은 음의 실수), 로그는 실수에서만(밑은 양수이고 1이 아니다), `log(x)`는 상용로그, 반올림은 0에서 먼 쪽으로. 단, 실수 범위의 방정식·부등식(기본)은 실수 산술로 푼다. 거기서는 $\sqrt{x}\sqrt{x-5}$가 $x<5$에서 정의되지 않으므로, 허수끼리 곱해 실수가 되는 해를 들이지 않는다(연립방정식의 나머지 식도 마찬가지).

## 범위: 중등부터 대학까지

서비스가 다루는 진도는 중학교부터 대학교까지다. 지금 콘텐츠는 고1까지이지만 검증기는 처음부터 그 범위를 보고 만들었다.

| 영역 | 지금 되는 것 |
|---|---|
| 수와 연산 | 분수·소수(정확한 유리수), 거듭제곱, 제곱근, 절댓값, 최대공약수·최소공배수, 나머지, 복소수 |
| 방정식 | 일차·이차·고차(중근 포함), 분수방정식(무연근 제외), 절댓값·무리방정식(제곱해서 생기는 해 제외), 연립일차(정확 소거), 한 식이 미지수를 일차로 주는 연립이차, 구간을 준 삼각·지수·로그방정식 |
| 부등식 | 일차·이차·고차·분수·절댓값·무리 부등식의 해집합(끝점의 열림·닫힘 포함), 그 안의 정수·자연수의 개수·합·최대·최소 |
| 식 | 대입·전개·인수분해가 맞는지(항등식), 식으로 된 보기 |
| 함수 | 문제가 정의한 함수, 합성, 역함수 값(방정식으로) |
| 경우의 수·확률·통계 | 순열·조합·중복조합·계승, 평균·중앙값·분산·표준편차(모집단·표본) |
| 미적분 | 미분계수(곱·몫·연쇄법칙, 삼각·지수·로그·역삼각·쌍곡 함수, $x^x$ 꼴), 고계도함수, 정적분(수치, 또는 부정적분으로 정확히), 극한(수치, 양쪽·한쪽·무한대), 유한 합·곱 |

**아직 안 되는 것** — 다음 순서로 넓힌다.

1. 행렬과 벡터(행렬식·역행렬·고윳값은 「확인」 방향으로: $AB=I$, $\det(A-\lambda I)=0$)
2. 무한 구간의 적분(이상적분), 급수의 수렴과 합
3. 확률분포(이항분포는 지금도 `nCr`로 된다. 정규분포는 표준정규분포 함수가 필요하다)
4. 미분방정식(해를 대입해서 확인하는 방향), 다변수 미적분(편미분·중적분)
5. 미지수 일차식이 없는 연립방정식(예: $x^2+y^2=25,\ x^2-y^2=7$) — 지금은 「풀 수 없음」으로 미확인
6. 증명·서술형·작도·그림을 읽어야 하는 문제는 이 방식으로 검증하지 않는다

## 이 검사가 보지 않는 것

**주장만으로는 지문이 정말 그 계산을 묻는지 모른다.** 「남은 양」을 묻는 지문에 덧셈 주장을 붙이면 주장·정답·보기가 서로 다 맞아서 통과한다. 주장에 지문에 없는 숫자가 있으면 경고(`prompt-numbers`)는 하지만 그 이상은 알 수 없다.

이 틈은 **독립 풀이**가 막는다. 문제를 만든 요청과 다른 요청(또는 다른 모델)에게 지문과 보기만 주고 풀게 한 답을 `independent`로 넘기면, 검증기가 그 답을 채점기에 넣어 정답 키가 받아들이는지 본다. 받아들이지 않으면 `independent-disagrees`(미확인)다 — 지문이 주장과 다른 것을 묻거나, 푼 쪽이 실수한 것이므로 사람이 본다. 위의 「남은 양」 예는 검사 파일에 그대로 있다: 주장만으로는 통과하고, 독립 풀이를 넣으면 걸린다. 독립 풀이를 요청하는 일 자체(어느 모델에 어떤 프롬프트로)는 [생성 흐름](#생성-흐름)이 한다.

기존 문항 2,320개에 주장을 자동으로 붙일 수도 없다. 지문의 수식을 기계로 뽑아 계산해 보면 114개가 뽑히는데, 그중 22개가 정답 키와 어긋난다. 어긋난 22개는 모두 정답 키 오류가 아니라 **수식에 대한 다른 것**을 묻는 문제였다(「$\frac58$의 분모는?」, 「$0.48$의 소수 둘째 자리 숫자는?」). 주장은 문제를 쓰는 쪽이 선언해야 한다.

### 학습자: AI 맞춤 연습

2026-10-16 · 코드: [`src/server/ai-practice.ts`](../src/server/ai-practice.ts), [`src/shared/ai-practice.ts`](../src/shared/ai-practice.ts), 화면: [`ai-practice.tsx`](../src/features/learning/ai-practice.tsx)

AI가 학습 기록을 읽고 무엇이 약한지, 무엇을 보강해야 하는지, 무엇이 헷갈리는지를 정해 문제를 낸다. 범위는 **전체 기록**, **코스 하나**, **수업 하나**다.

| 단계 | 누가 | 무엇을 |
|---|---|---|
| 1. 기록 정리 | 서버 | 범위 안의 첫 답(그 범위 수업에서 푼 것, 또는 그 범위가 가르치는 개념을 물은 것)을 모은다. 개념별 상태와 첫 답의 맞음·틀림, 되풀이된 실수(이름 붙은 실수와 답 모양 패턴 모두), 최근 첫 답이 틀린 문제 최대 12개를 지문·학습자의 답·정답과 함께 한 장으로 만든다. 첫 답이 3개 미만이면 만들지 않는다 |
| 2. 분석·계획 | Claude Sonnet 5.5, medium | 학습자에게 보일 **진단**(2~3문장, 해요체, 한 일을 구체적으로)과 **연습할 것 1~4개**(개념·초점·겨냥할 실수·이유 한 문장·문제 수)를 낸다. 초점은 `confused`(되풀이된 실수), `weak`(약한 개념), `reinforce`(맞힌 개념을 다른 상황에서) |
| 3. 계획 정리 | 서버 | 기록이 이름한 개념과 카탈로그가 아는 실수만 남기고, 문제 수를 8에 맞춘다. 쓸 게 없으면 첫 답이 많이 틀린 개념으로 대신한다 |
| 4. 출제·검증 | 위의 세 단계 | 연습할 것마다 병렬로 쓰고 → 따로 풀고 → 판정. `verified`만, 겨냥한 실수가 있으면 그 이름표가 달린 것만 남긴다 |
| 5. 얼리기 | 서버 | `GeneratedProblemSet`(범위·계획·상태) + `generated` 문항으로 얼리고, 진단과 문제별 이유를 과제의 `policySnapshot.ai`에 담아 학습자만의 연습으로 연다 |

- **요청은 바로 돌아온다.** 1단계까지 확인하고 `pending`을 남긴 뒤 2~5단계는 서버에서 이어서 한다(실측 20초 안팎, 프록시 시간 제한 때문). 화면은 4초마다 상태를 다시 읽어 단계 문구를 보여 주고, 끝나면 요청한 화면에 있을 때 과제를 연다. 다른 화면으로 가도 계속 만든다. 10분 넘게 `pending`이면 실패로 본다(재시작).
- **진입점 넷:** 내 학습(전체 기록, 오늘의 추천 아래), 학습 기록 맨 위(전체 기록), 수업을 마친 화면(그 수업), 수업 목록에서 코스를 펼친 카드 줄(그 코스). 같은 범위로 열어 두고 다 풀지 않은 연습이 있으면 「이어서 풀기」.
- **한 번에 8문제, 학습자당 하루 3번**(실패도 센다). 과제 위에는 「AI가 「범위」 기록에서 본 것」과 진단, 문제 위에는 그 문제를 낸 이유가 붙는다.
- 첫 실제 실행(전체 기록, 분수 두 수업의 첫 답 10개 중 8개 틀림): 21초, 연습할 것 셋(분모끼리 더하기·동치분수·통분), 8문제 계획 중 6문제가 검증을 통과해 열렸다.

### 학습자: 모아 풀기를 채운다

학습 기록의 헷갈림 요약에서 되풀이된 실수의 **이것만 모아 풀기**를 누르면, 먼저 지금처럼 그 실수 이름표가 달린 카탈로그 문항을 고른다([평가 설계](assessment-design.md)). **6개에 모자라면 모자란 만큼만 모델이 쓴다.**

- 쓰는 근거는 **이 학습자의 실제 오답**이다. 그 실수로 읽힌 오답 최대 4개의 지문·학습자가 쓴 답·정답을 writer에게 주고, 같은 개념·같은 수준에서 이 실수를 하면 바로 드러나는 새 문제를 쓰게 한다. 과정 이름과 개념은 그 오답의 문항에서 가져온다.
- **`verified`만 남기고, 그중에서도 그 실수 이름표가 달린 예상 오답이 있는 문제만** 남긴다. 사람이 읽고 고르는 단계가 없기 때문이고, 이름표가 없으면 틀려도 그 실수에 대해 아무것도 말해 주지 않기 때문이다.
- 남긴 문제는 **학습자가 풀기 전에 얼린다** — `PublishedProblem`의 종류 `generated` 행과 그 블록. 묶음은 `GeneratedProblemSet`(누구를 위해, 어느 실수, 몇 개 요청해 몇 개 남겼는지)이고 id는 `generated:`로 시작한다. 채점·힌트·해설은 발행 문항과 같은 길을 그대로 쓴다.
- **그 학습자만 받는다.** 다른 학습자의 모아 풀기는 `generated`를 읽지 않는다. 그 학습자 자신의 다음 모아 풀기는 아직 맞히지 못한 생성 문제를 다시 쓰므로, 같은 것을 또 만들지 않는다. 계정을 지우면 함께 지워진다. `content:verify`의 「판본에 속하지 않는 행」 세기에서는 빠진다.
- 생성은 모아 풀기 트랜잭션 **밖에서 먼저** 한다(15~40초). 버튼은 「문제 준비 중… (새로 만들면 30초쯤)」이라고 말하고, 과제 화면은 「이 중 N문제는 AI가 내 오답을 보고 새로 만든 문제예요」라고 밝힌다.
- **하루 5번**(학습자당, 남긴 것이 없어도 센다)까지만 쓴다. 넘으면 카탈로그 문항만으로 열고, 그것도 없으면 「오늘은 새 문제를 더 만들 수 없어요」라고 말한다. 모델이 실패해도 카탈로그 문항으로 연다.
- 모델을 쓸 수 있으면 추천 카드의 문제 수는 6이다.

첫 실제 실행(2026-10-16, 「1을 소수로 보기」, 카탈로그 2문항): 4개를 요청해 4개가 왔고 2개가 `verified`, 그중 이름표가 맞는 1개가 남아 3문항으로 열렸다. 「소수인 것은?」처럼 판단을 묻는 문제를 검증기가 읽지 못해서였고, 같은 날 판정 함수와 `property`를 더해 판단형 네 묶음의 통과가 17/24에서 22/24로 올랐다(위 표). 말로 된 보기(「소수는 모두 홀수이다」)는 여전히 읽지 않는다 — 「소수」가 prime과 decimal 둘 다라 문장을 짐작하면 틀린 문제를 통과시킬 수 있다.

### 작성자: 편집 화면

편집 화면에서 활동(「문제」 블록)을 고르면 문항 목록 아래에 **AI로 문제 만들기**가 있다. 작성자는 다룰 개념, 겨냥할 실수(오개념 이름표, 고르지 않으면 쓰는 쪽이 고른다), 문제 수(최대 6), 형식(객관식·답 쓰기·섞어서), 더 바라는 것을 정한다. 그 활동에 이미 있는 문항의 지문과 정답도 함께 보내, 같은 문제와 같은 정답을 피하게 한다.

| 단계 | 누가 | 무엇을 받고 무엇을 내는가 |
|---|---|---|
| 1. 쓰기 | Claude Sonnet 5.5, effort `medium` | 시스템 프롬프트는 [작성 지침](lesson-writing-guide.md)의 「지침」 절 그대로, 그 뒤에 이 일의 형식(문항의 항목, 주장 쓰는 법, 오개념 이름표 목록)이 붙는다. 문항마다 지문·보기·정답·예상 오답과 그 잘못된 계산·주장·힌트·해설을 structured output으로 낸다 |
| 2. 따로 풀기 | 같은 모델, 별도 요청, effort `medium` | **지문과 보기만** 받는다. 주장·정답·예상 오답은 보지 않는다. 답만 낸다 |
| 3. 판정 | 서버 | `verifyProblem`에 2의 답을 `independent`로 넣는다. 따로 푼 답이 없으면(요청 실패) `independent-missing`으로 미확인 |

- **아무것도 저장하지 않는다.** 결과는 작성자가 고르는 목록이다. `검증됨`은 「활동에 넣기」, `확인 필요`는 이유를 보여 주고 「읽어 봤어요, 넣기」, `틀림`은 넣을 수 없다. 넣은 문항은 손으로 쓴 문항과 같다 — 고치고, 저장하고, 발행할 때 판본으로 얼린다.
- **편집기가 담을 수 없는 모양**(주관식인데 답 칸이 읽지 못하는 정답, 보기 이름이 a~f가 아님, 길이 초과, 글 안에 응답 형식의 조각)은 버리지 않고 `output-invalid`(틀림)로 보여 준다. 요청한 수보다 적게 오면 화면이 그렇게 말한다.
- **답 칸이 받지 않는 예상 오답**(정수로 답하는 문제의 분수)은 문제를 버리지 않고 그 이름표만 빼며 `misreading-dropped`(경고)로 남긴다. 이름표는 없어도 되는 것이고, 빼서 틀린 정답이 통과할 일은 없다. 계산이 닿지 않는 예상 오답은 그대로 틀림이다 — 지어낸 오답은 해설에도 들어가 있기 때문이다.
- 두 요청 모두 server-side fallback(`fallbacks: "default"`)을 켠다. 거절이 남으면 화면에 그렇게 말한다. 한 계정은 한 번에 한 생성만 돌린다.
- `ANTHROPIC_API_KEY`가 없는 배포에서는 이 기능이 화면에 나오지 않는다(작업 공간의 `problemWriter`). 운영에서는 배포 job이 같은 이름의 저장소 secret을 `ENV_FILE`과 따로 읽어 VM의 `app.env`에 한 줄로 더한다. secret을 지우고 다시 배포하면 꺼진다.
- 요청마다 토큰 사용량을 `{"event":"problem_generation"}` 한 줄로 남긴다. 계정별 한도와 비용 집계는 아직 없다.

**작성 지침이 곧 프롬프트다.** 지침을 고치면 `npm run guide:sync`로 `src/server/writing-guide.ts`를 다시 만든다. 둘이 다르면 검사(`tests/problem-generation.test.ts`)가 실패한다. 배포된 서버는 `docs/`를 읽을 수 없어서 사본을 둔다.

**아직 안 하는 것.** 주장은 결과에만 있고 판본에 저장되지 않는다 — 작성자가 넣은 뒤 정답을 고치면 다시 검증되지 않는다. 수업 본문(설명·예시)은 쓰지 않는다. 학습자 화면의 즉석 출제는 [평가 설계](assessment-design.md)의 순서대로 헷갈림 요약을 읽는 일 뒤에 온다.

화면 없이 같은 흐름을 돌려 보려면:

```sh
ANTHROPIC_API_KEY=… npm run problems:generate -- request.json --out result.json
```

## 쓰는 법

```sh
npm run problems:check -- problems.json
npm run problems:check -- problems.json --independent answers.json
```

`problems.json`은 생성 결과 배열이다. 항목마다 `prompt`, `answer`(문항이 저장하는 형식 그대로), `misreadings`(`answer`·`misconception`, 선택으로 잘못된 계산 `expression`), `solves`가 있다. `answers.json`은 지문만 보고 푼 답을 같은 순서로 담은 배열이다(`["-4", "3/4", "a"]` 또는 `[{"n": 1, "answer": "-4"}, …]`). 코드에서는 `verifyProblem({ prompt, answer, misreadings, solves, independent })`가 판정과 이유를 돌려준다(`src/core/verify/verify.ts`).

## 적대적 검토

PR 전에 두 번, 네 갈래(틀린 문제를 통과시키는 길, 방정식 풀이, 보기 읽기, 수치 계산)로 나눈 검토자가 결함을 찾고 다른 검토자가 재현해 확인했다. 1차에서 27개, 1차 수정을 겨눈 2차에서 25개가 확인됐고 모두 고쳤다. 사례는 검사 파일의 「cases found by adversarial review」에 하나씩 남아 있다. 고친 것 중 의미가 바뀐 것:

- 도(°)는 언제나 라디안 값이다. 1차에서 「삼각함수가 없는 식에서는 도를 그냥 수로 읽는다」로 고쳤다가, `given`으로 넘긴 각이 사인에 닿을 때 30라디안이 되는 결함을 낳아 2차에서 되돌렸다. 도로 센 답은 `claim-degrees`로 잡는다.
- 무리수 계수 다항식의 중근은 반올림 오차가 만드는 퍼짐($\varepsilon^{1/m}$)으로 묶는다. 묶음이 근을 가르지 못하면(추정값에서 다항식이 0이 아니거나, 두 근이 합친 중복도의 퍼짐 안에 있으면) 개수를 짐작하지 않고 `unstable`로 실패한다.
- 부등식 해집합에서 분모의 근(극)은 늘 뺀다. 제곱근의 정의역 끝은 닫는다. 수치 오차로 판정하지 않고 끝점이 어디서 왔는지로 정한다.
- 구간 탐색은 0인 구간이 이어지면(항등식, `floor(2x) = 3`) 근을 세지 않고 실패한다.
- 수치 적분은 처음부터 16칸으로 나눠 시작한다. 한 번의 15점 규칙이 $[0, 10000]$에서 $e^{-x}$를 0으로 본 결함 때문이다.

## 설계 결정

- **의존성을 더하지 않았다.** 수식 처리 라이브러리를 쓰지 않고 유한한 문법과 정확한 유리수 산술을 직접 구현했다. 모델이 쓴 텍스트를 서버에서 읽으므로 코드 실행이 없어야 하고, 학교 계산은 근사가 아니라 정확해야 하며, 저장소가 학습자 답 채점에서 이미 같은 원칙(`src/shared/math-expression.ts`)을 따른다.
- **푸는 대신 확인한다.** 어려운 쪽(부정적분, 해)은 모델이 내고 서버는 쉬운 쪽(미분, 대입)으로 확인한다. 방정식은 모든 해를 담는 후보 집합(분자의 근, 절댓값의 두 갈래, 제곱한 식의 근)을 만든 뒤 원래 식에 대입해 걸러서, 해를 잃지도 더하지도 않는다.
- **연립방정식은 잃지 않는 소거만 한다.** 미지수 하나를 다른 식에 대입할 때, 그 미지수의 계수가 다른 미지수에 따라 0이 될 수 있으면 대입하지 않는다(나누면 해를 잃는다).
- **채점은 채점기가 한다.** 정답 키와 예상 오답은 `gradeAnswer`에 그대로 넣어 본다. 검사기가 채점 규칙을 따로 갖지 않으므로 둘이 어긋날 수 없다.
