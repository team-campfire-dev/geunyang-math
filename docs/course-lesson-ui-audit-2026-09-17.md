# 코스·수업 UI 직접 사용 점검

2026-09-17 · 로컬 `http://127.0.0.1:3017` · `codex/course-centered-ui` / `2101dba` 기준.

코스 생성 → 수업 생성 → 문항 복제·정답 수정 → 저장·검증·발행 → 새 초안 생성·검색 → 뜻풀이 편집 → 학습자 목록·수업 미리보기를 실제 브라우저에서 확인했다. 데스크톱 1440×900과 모바일 폭 375에서 점검했다. 관리자 열린 편집 환경이며, 일반 작성자 권한·동시 편집·네트워크 단절·실제 모바일 기기는 이번 범위에 포함하지 않았다.

**우선순위는 정답 표시와 입력 보존 → 저장·발행 피드백 → 검색·화면 이동 → 모바일 편집 동선 순이다.** 아래 01–05, 07–08은 재현한 동작 오류이며, 06·09·10은 실제 동작을 확인한 뒤 제안하는 제품 보완 사항이다. P1은 편집 내용의 신뢰·보존, P2는 주요 흐름의 혼동·불편, P3는 일관성 개선을 뜻한다.

제품 코드는 수정하지 않았다. 테스트용 코스 1개, 수업 2개, 초안 5개와 발행된 테스트 판본·문항·블록은 연결된 수강·과제가 없음을 확인한 후 정리했다. 기존 콘텐츠·계정·학습 기록은 변경하지 않았다.

## 01 · P1 · 다른 문항을 선택해도 정답 칸이 이전 문항의 값을 표시한다

재현:

1. 수업의 연습 단계에서 1번 문항 정답을 `3`으로 저장한다.
2. 문항을 복제하고 2번 정답을 `7`로 저장한다.
3. 다시 1번 문항을 선택한다.

결과: 편집기 제목은 **1번 문항**인데 정답 입력칸은 **7**이다. 실제 발행 데이터는 1번 `3`, 2번 `7`로 저장되어 있었다. 화면과 채점 기준이 달라 작성자가 잘못된 정답을 검수하거나 덮어쓸 수 있다.

관련 확인: 정답에 `abc`를 입력하면 오류 안내는 나오지만 상단은 여전히 **저장됨**이고 발행 버튼도 활성화된다. 안내대로 이전 유효 정답이 남는 구조지만, 현재 입력의 유효성과 문서 저장 상태가 분리되어 있다. 이 상태로 발행을 완료하는 테스트까지 하지는 않았다.

원인 근거: [problem-editor.tsx:19](../src/features/authoring/problem-editor.tsx#L19)의 `AnswerField`가 처음 받은 정답만 로컬 상태에 넣고, 문항 변경 시 동기화하지 않는다. [authoring-workspace.tsx:494](../src/features/authoring/authoring-workspace.tsx#L494)에서도 문항별 편집기 재생성을 보장하지 않는다.

수정 방향: 문항 선택·되돌리기에 정답 칸을 동기화하고, 잘못된 정답 입력이 남아 있으면 저장 상태와 발행 가능 여부에 반영한다.

## 02 · P1 · 코스·뜻풀이에서 작성 중인 입력이 경고 없이 사라진다

재현 A: **코스 만들기** → 이름·소개 입력 → 상단 **코스 만들기**를 다시 클릭한다. 입력칸이 비고 저장 버튼이 비활성화된다.

재현 B: 수업 설정의 **이 수업의 뜻풀이 관리** → **새 뜻풀이** → 새 개념 이름·한 줄 요약 입력 → **뜻풀이 닫고 수업으로** → 다시 관리 패널을 연다. 작성 폼과 내용이 사라지고 빈 목록으로 돌아온다. 저장 여부를 묻거나 복구하는 동선이 없다.

영향: 수업 본문은 자동 저장되지만 주변 폼은 수동 저장이다. 같은 편집 화면 안에서 보존 규칙이 달라 긴 뜻풀이를 잃기 쉽다.

원인 근거: [course-library.tsx:40](../src/features/authoring/course-library.tsx#L40)의 폼 재초기화, [authoring-workspace.tsx:446](../src/features/authoring/authoring-workspace.tsx#L446)의 조건부 패널 제거.

수정 방향: 열린 생성 폼의 재실행은 기존 입력에 포커스를 주고, 뜻풀이 편집값은 닫았다 열어도 유지한다. 실제로 버리는 동작에는 저장·버리기 선택을 둔다.

## 03 · P2 · 저장 실패의 원인을 찾기 어렵고 검증·저장 안내가 서로 충돌한다

재현:

1. 정상 초안을 검증해 **발행 검증을 통과했어요**를 표시한다.
2. 수업 제목을 모두 지우고 자동 저장을 기다린다.
3. 코스로 돌아가기 버튼을 누른다.

결과: **저장하지 못했어요 / 입력 형식을 확인해 주세요**만 표시되고, 문제가 있는 제목 칸에는 오류 표시가 없다. 이전 검증 성공 안내도 남아 있다. 코스로 돌아가기 역시 실패한 저장을 재시도하므로 이동하지 않는다.

추가 관찰: 제목 등 편집값을 마지막 저장 상태와 동일하게 복원하면 **지금 저장**은 비활성화되지만 실패 안내는 남는 상태도 확인했다.

원인 근거: [authoring-workspace.tsx:139](../src/features/authoring/authoring-workspace.tsx#L139)의 저장 처리와 동일 스냅샷 조기 반환, [223](../src/features/authoring/authoring-workspace.tsx#L223)의 검증 안내, [231](../src/features/authoring/authoring-workspace.tsx#L231)의 이탈 처리.

수정 방향: 필드별 오류와 이동 링크를 표시하고, 문서 수정 시 이전 검증 성공을 무효화한다. 저장 상태로 되돌렸을 때 실패 상태도 해제하며, 저장 실패 중에는 명시적으로 변경을 버리고 나갈 수 있게 한다.

## 04 · P2 · 새 개념 이름에서 Enter를 누르면 수업이 생성된다

재현: 코스에서 **수업 추가** → 수업 이름 입력·기존 개념 선택 → **목록에 없는 개념 추가** 펼침 → 새 개념 이름 입력 → Enter.

결과: 개념을 추가하는 대신 수업이 즉시 생성되고 편집기로 이동한다. 새 수업의 개념은 기존에 고른 개념이며, 입력한 새 개념은 추가되지 않았다.

원인 근거: [course-library.tsx:53](../src/features/authoring/course-library.tsx#L53)의 부모 폼은 수업 생성으로 제출되며, 새 개념 필드도 같은 폼 안에 있다. **개념 추가하고 선택**만 `type="button"`이다.

수정 방향: 새 개념 입력의 Enter 동작을 개념 추가로 연결하거나 별도 폼으로 분리한다. 수업 생성은 별도의 명확한 제출 동작으로 남긴다.

## 05 · P2 · 화면에 보이는 초안 제목으로 수업을 찾을 수 없다

재현: `QA 수업 A - 기본 생성 상태`를 발행 → **수정 시작** → 초안 제목을 `QA 바뀐 초안 제목`으로 저장 → 코스 목록의 **수업 찾기**에 `바뀐` 입력.

결과: 카드 안에 변경한 초안 제목이 표시되어 있었는데 검색하면 **찾은 수업이 없어요**가 나온다. 카드 대표 제목은 이전 발행판 제목이다.

원인 근거: [course-library.tsx:82](../src/features/authoring/course-library.tsx#L82)가 `lesson.title`만 검색하고 초안 제목은 제외한다.

수정 방향: 발행판과 열린 초안 제목을 함께 검색하고, 어떤 제목에 일치했는지 카드에서 드러낸다.

## 06 · P2 · 미작성 기본 문구를 발행 전에 걸러 주지 않는다

재현: 새 수업 생성 후 소개·설명·문제 지문을 기본값으로 둔다. 이번 테스트에서는 정답 수정과 문항 복제만 진행했다. **검증 → 발행 → 발행할게요**를 실행한다.

결과: 발행이 성공한다. 학습자 수업 목록에는 **한 줄 소개를 적어 주세요.**, 수업 미리보기에는 **새 단계 / 여기에 설명을 씁니다.**가 그대로 노출된다.

구조 검증 통과와 콘텐츠 작성 완료는 서로 다르다. 현 검증의 오류라고 단정하기보다, 실수로 미완성 수업을 공개하기 쉬운 발행 UX의 보완점이다.

관련 구현: [server/authoring.ts:627](../src/server/authoring.ts#L627)에서 안내용 문장을 실제 콘텐츠 기본값으로 생성한다.

수정 방향: 안내 문구를 placeholder로 옮기거나, 미작성 기본값을 발행 전 점검에 포함한다. 확인 화면에 미작성 위치·공개될 소개·문항 수를 보여 준다.

## 07 · P2 · 새로고침하면 편집 중이던 수업·단계로 돌아오지 못한다

재현: 저장된 수업 초안의 연습 단계에서 문항을 선택한 뒤 새로고침한다.

결과: 수업 편집기가 아니라 **어떤 코스를 준비할까요?** 화면으로 돌아온다. 저장된 초안은 남아 있으나 코스·수업을 다시 찾아야 한다. 코스와 수업 편집 사이에서 URL은 계속 `/authoring`이다.

원인 근거: [authoring-workspace.tsx:32](../src/features/authoring/authoring-workspace.tsx#L32)의 초안·단계 상태와 [53](../src/features/authoring/authoring-workspace.tsx#L53)의 선택 코스가 컴포넌트 상태에만 있다.

수정 방향: 코스·초안·단계를 URL에 담아 새로고침, 링크 공유, 브라우저 앞뒤 이동의 기준을 맞춘다. 이번 점검에서는 새로고침만 직접 재현했고 앞뒤 이동은 별도 테스트하지 않았다.

## 08 · P3 · 새 수업이 직전에 보던 다른 수업의 단계에서 열린다

재현: 수업 A의 두 번째 **연습** 단계에서 코스로 나와 새 수업 B를 만든다.

결과: 새 수업 B도 첫 설명이 아니라 **02 연습**에서 시작한다. B는 처음 만든 수업이므로 해당 수업에서 마지막으로 보던 위치가 아니다.

원인 근거: [authoring-workspace.tsx:81](../src/features/authoring/authoring-workspace.tsx#L81)이 새 초안을 열 때도 기존 단계 인덱스를 유지한다.

수정 방향: 새 수업은 첫 단계에서 시작하고, 이어 쓰기 복원이 필요하면 수업별 마지막 위치를 저장한다.

## 09 · P2 · 모바일에서 문항 본문과 정답 편집기가 떨어져 있다

재현: 폭 375에서 연습 단계의 **1번 문항**을 선택한다.

결과: 본문 입력칸에 포커스가 가지만 정답·개념·힌트 편집기는 수업 시트 아래에 있어 화면 밖에 남는다. 편집기 이동 링크는 본문 위에 있다. 문제를 보면서 정답과 힌트를 점검하려면 위아래를 반복해서 이동해야 한다. 화면이 깨지는 오류라기보다 작업 동선의 문제다.

관련 구현: [editor.css:283](../src/app/editor.css#L283)에서 편집기가 전체 시트 아래로 이동하고, [authoring-workspace.tsx:458](../src/features/authoring/authoring-workspace.tsx#L458)의 이동 링크는 시트 앞에 있다.

수정 방향: 선택한 문항 가까이에 편집 진입점을 두거나, 문제 요약을 포함한 하단 편집 패널을 검토한다. 본문을 쓰려는 선택과 정답을 편집하려는 선택을 구분해야 한다.

## 10 · P2 · 코스 목록에서 발행한 수업을 읽기만 하는 동선이 없다

재현: 수업 발행 후 코스 목록으로 돌아간다. 열린 초안이 없는 발행 수업 카드를 확인한다.

결과: 제목은 정적 텍스트이고 주 동작은 **수정 시작**이다. 코스 목록 안에서는 새 초안을 만들지 않고 발행판을 열어 검수하기 어렵다. 학습자 화면으로 별도 이동하면 확인할 수 있다.

관련 구현: [course-library.tsx:85](../src/features/authoring/course-library.tsx#L85)의 카드 제목·상태와 [88](../src/features/authoring/course-library.tsx#L88)의 수정 시작 버튼.

수정 방향: **발행판 보기**와 **새 초안으로 수정**을 분리한다. 발행판을 읽는 동작이 초안을 만드는 부수 효과를 갖지 않게 한다. 판본 이력은 필요에 따라 그 화면에 연결한다.

## 권장 작업 묶음과 확인 기준

1. **편집값 신뢰·보존:** 01·02·03. 문항 전환/되돌리기의 정답 일치, 폼 재열기 시 입력 유지, 잘못된 필드 표시와 저장 상태 복구를 확인한다.
2. **생성·검색·발행:** 04·05·06. 개념 Enter와 수업 생성 구분, 초안 제목 검색, 기본 문구가 남은 발행의 경고·차단 정책을 확인한다.
3. **화면 이동·검수:** 07·08·09·10. 새로고침 위치 복원, 새 수업 첫 단계, 모바일 문항-정답 이동, 초안 생성 없는 발행판 열기를 확인한다.

이번에는 관찰·수집만 수행했으며 자동 테스트나 빌드를 다시 실행하지 않았다. 후속 수정에서는 상태 전환 버그를 회귀 테스트로 남기고, 모바일 편집 동선과 발행 흐름은 브라우저로 다시 확인해야 한다.


## 후속 수정 및 재검증

위 01–10 항목을 후속 PR에서 수정했다. 정답은 문항별 원문과 답안 기준을 함께 보관하고 잘못된 입력을 다른 문항으로 이동해도 유지한다. 반복 생성 버튼·뜻풀이 접기는 입력을 보존하며, 화면 전환에서 저장하지 않은 입력을 확인한다. 제목·소개를 지운 초안도 자동 저장하되 발행은 차단하고 해당 필드로 안내한다. 개념 추가의 Enter가 수업 생성까지 실행하지 않도록 분리했고, 초안 제목 검색과 발행판 읽기를 추가했다. 새 수업은 첫 단계에서 시작하고 URL의 코스·초안·단계를 새로고침으로 복원한다. 브라우저 앞뒤 이동 이력은 이번 범위에 포함하지 않았다.

사용자 정정에 따라 개념은 분수·분자·분모 같은 원자적 단위로 맞췄다. 개념별 뜻풀이와 관련 수업을 함께 조회하며, 뜻풀이 작성 중 만든 개념도 수업에서 선택한다. 기존 3개 수업·진단을 새 개념으로 재작성했다. 정수·소수·분수 답안 설정, 수직선·좌표평면·삼각형 그림 틀을 추가하고 개념 선택·모바일 배치를 수정했다.

검증 결과: 타입 검사, MySQL 포함 테스트 380개, 웹 빌드와 모바일 정적 빌드 통과. 브라우저에서 문항별 정답 전환과 잘못된 답 저장 차단, 빈 제목 자동 저장·복구, 반복 수업 추가 입력 보존, 개념 Enter, 새로고침 위치, 새 수업 첫 단계, 발행판 열기, 개념 뜻풀이 연결을 확인했다. 375px 화면에서 본문·그림·뜻풀이와 편집 이동을 점검했다. 로컬 콘텐츠 검증은 수업 3개·문제집 10개·문항 25개·뜻풀이 7개를 확인했다. 임시 QA 코스와 미발행 수업은 정리했다.
