# geunyang math 제품 방향

2026-09-14 사용자와 합의한 방향. 현재 구현 여부는 [구현 현황](implementation-status.md), 운영 근거는 [배포 기록](deployment.md)을 기준으로 한다.

성인이 기초 수학을 자신의 속도로 다시 배우는 웹 서비스다. 초기에는 AI 없이 기본 수업, 학습 기록, 개인화의 근거, 복습 과제를 먼저 만든다. 최초 콘텐츠는 분수에서 시작해 2026-09-18에 소수 · 비와 비율 · 정수와 유리수까지 넓혔다. 학교 교육과정이 분수 뒤에 두는 순서를 따랐고, 다음 칸은 일차방정식이다.

> **정해지지 않은 것: 누구를 위한 서비스인가.** 위의 첫 문장은 성인의 기초 재학습을 말하는데, 2026-09-18에 사용자는 중학생·고등학생·대학생·직장인을 대상으로 말했다. 이 차이는 문구의 문제가 아니다 — 지금까지의 설계 대부분이 「기초 재학습 성인」을 전제로 내려졌고, 특히 **진단이 개념 수에 정비례해 길어지는 전수 확인 방식**이라 대상이 넓어지면 쓸 수 없다. 대상을 정하고 그 위에서 진단과 코스 모델을 다시 보는 것이 콘텐츠를 더 넓히는 일보다 앞선다.

## 지켜야 할 경계

- 수업은 설명·예제·연습·확인·정리로 구성한다. 학급은 추후 별도의 LearningGroup으로 모델링한다.
- 콘텐츠 블록은 kind와 typeVersion으로 식별한다. 스키마 검증과 렌더러를 등록해 그래프·도형 등 형식을 추가한다. 필수 미지원 블록은 학습 완료를 막고, 선택 블록은 대체 설명을 제공한다.
- 기본 콘텐츠와 이후 발행 콘텐츠의 운영 원본은 DB다. 블록 JSON은 DB 내부의 확장 가능한 문서 형식으로 유지한다.
- 발행한 수업과 문항은 판본을 고정한다. 기존 수강·과제 기록을 편집으로 바꾸지 않는다.
- 본문 용어의 풀이를 어디에 붙일지는 수업을 쓴 사람이 정한다. 낱말에 용어를 걸었다는 것이 곧 여기서는 설명해도 된다는 판단이고, 서버가 학습자의 진도를 보고 그것을 뒤집지 않는다. 문항이 평가하는 개념을 그 문항 안에서 설명하는 것만 발행 단계에서 막는다.
- 개인화는 목표·시간·선수 개념·독립 풀이·도움 사용·지연 복습의 근거를 사용한다. 시청 완료나 반복 정답만으로 숙달을 선언하지 않는다.
- 과제 정의, 대상자 배정, 제출 회차, 개별 풀이, 평가 기록을 나눈다. 개인 복습부터 시작하되 수강 없이도 과제를 배정할 수 있게 한다.
- 개인과 기관의 소유 범위, 교사·학생 권한, 고정 과제와 개인화 가능한 과제의 정책을 구분한다. 기관 UI는 첫 버전 범위에 포함하지 않는다.
- 정답·채점·권한 검사는 서버에 둔다. 공개 콘텐츠 응답과 모바일 번들에 정답을 넣지 않는다.

## 확장 순서

1. **완료:** 기본 수업의 끝까지 학습·과제 제출, Google 로그인·기록 복원, 운영 배포.
2. **첫 규칙 구현 완료:** 선택형 진단, 선수개념·첫 풀이 기반 추천, 시간별 복습과 추천 이력. 문항·규칙의 학습 효과 검증과 반복 복습은 후속 작업.
3. **DB 관리 기반 완료:** 기본 수업·진단·개념 이전, import/export/verify와 판본 보존. 이를 사용해 콘텐츠를 검수·확대하고 초안·미리보기·발행 편집 환경을 만든다.
4. **후속:** 편집기와 같은 스키마로 AI가 개인화 초안을 만들고 검증·검토 후 발행한다.
5. **후속:** 학원·학교의 조직·학급·배정·마감·재제출·평가 정정 기능을 구현한다. 기관 기능은 AI 도입을 기다려야 하는 구조가 아니며, 필요에 따라 순서를 조정한다.

AI는 별도의 자유 형식 강의 생성기로 붙이지 않는다. 편집기와 발행 검증을 공유하는 초안 작성자로 통합한다. 생성물의 수학적 정확성, 사용자 데이터 범위, 비용과 실패 복구를 검증한 뒤 확대한다.

## 인프라와 모바일

Constella의 Next.js 웹/API 구조, Arongwalk의 입력 검증과 기록 저장, cooo의 실제 MySQL 통합 검사를 참고한다. 데이터베이스와 자격 증명은 프로젝트 단위로 분리한다.

서랍처럼 웹 UI를 정적으로 빌드해 Capacitor에서 재사용할 수 있도록 클라이언트 화면과 서버 API를 분리한다. 모바일은 동일한 학습 계약을 사용하고, 네이티브 인증·보안 저장소·오프라인 저장·스토어 빌드는 별도 단계에서 구현한다. 웹 미리보기 성공이나 정적 export 성공이 실제 기기 검증을 대신하지 않는다.
